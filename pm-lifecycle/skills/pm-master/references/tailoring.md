# 流程裁剪

> 只有**一条流程**（13 个阶段）。下面是常用的裁剪方式——**裁剪不是另一条流程，是同一条流程跳过某些阶段。**
> 阶段编号永远不变，跳过的阶段在任务清单里标注「已跳过（理由）」，方便断点续跑时判断。

## 裁剪表

| 裁剪名 | 跑哪些阶段 | 什么时候用 |
|---|---|---|
| **全量（从 0 到 1）** | -2 → 10 全部 | 全新产品，方向都还没定 |
| **立项** | -2, -1, 0, 1, 2, 3 | 只要论证方向和规划，暂不进开发 |
| **标准交付** | 0 → 9 | 方向已定的新项目（原九阶段流程） |
| **快速交付** | 4, 5, 6, 7, 8 | 已有明确需求，直奔文档与原型 |
| **只要文档** | 4, 5, 7, 8, 9（跳过 6） | 不生成前端代码 |
| **迭代** | 4, 5, 6, 7, 9 | 存量产品加功能，画像与路线图已有 |
| **上线体检** | 10 | 代码已存在（尤其 AI 生成），只做审计 |
| **单点** | 任一阶段单独跑 | 用户只要一份产出——此时不要起流程，直接按 SKILL.md 的单点路由表走 |

## 跳过判据

| 阶段 | 可以跳过当且仅当 |
|---|---|
| -2 战略框架 | 已有战略文档，或存量产品的迭代 |
| -1 上市与 ICP | 内部工具，或只做技术验证不涉及对外销售 |
| 0 市场调研 | 已有调研报告；**或已跑过阶段-1**（此时只需在滩头细分内做聚焦补充，不重做全市场扫描） |
| 1 用户画像 | 已有画像，且本次需求不涉及新客群 |
| 2 功能优先级 | 需求只有一个，无需排序 |
| 3 产品路线图 | 单次交付，不涉及多版本规划 |
| 4 需求澄清 | 用户已给出结构化需求 |
| 5 需求文档 | **不可跳过**——后续阶段全部依赖 `SPEC_SOURCE` |
| 6 前端原型 | 只要文档，或前端另有团队 |
| 7 测试用例 | 无质量交付要求（不推荐跳） |
| 8 操作手册 | 无终端用户或无需交付手册 |
| 9 发版说明 | 不对外发布 |
| 10 上线审计 | 代码非 AI 生成，或纯文档交付 |

## 换挡：默认档 vs 深度档

四个阶段有两个技能可选。**档位在 Step 0 问题3 就问定**（全部默认／全部深度／逐阶段问／混合指定），
不要等用户嫌浅了再补问。中途用户说「这步做深一点」仍可随时换。

单点路由（不起流程）命中这四类之一时，也要先问一句档位——问法见 `../SKILL.md` 单点路由表下方。

| 阶段 | 默认档（快，落盘） | 深度档（慢，带模型/模板/兜底） |
|---|---|---|
| 2 功能优先级 | `pm-feature-prioritization` | `pm-prioritization-engine`（RICE/ICE/Kano 交叉 + 敏感性分析 + 高分歧裁决） |
| 3 产品路线图 | `pm-roadmap` | `pm-roadmap-planner`（目标对齐/能力拆分/风险缓冲四步 + 甘特图 HTML） |
| 5 需求文档 | `req-doc`（SRS 真源）／`prd-writer`（PRD） | `pm-prd-spec`（五形态 + 字段级 + 线框图 + Word；**流程须代登记 SPEC_SOURCE**）<br>**`pm-prd-writer` 不可在流程内用**（不登记真源） |
| 数据分析（非固定阶段） | `pm-product-metrics`（指标体系/漏斗/留存框架） | `pm-analytics`（归因 + 决策建议 + HTML 报告） |

**换挡不改变阶段编号，也不改变产出路径。** 深度档产出更厚，但仍要落到该阶段约定的 `prd/` 文件（SRS 落 `dev/SRS/`）。
