## 阶段6：界面设计稿

**技能**：`ui-ux-pro-max`（设计侧只此一个：设计系统 + 材质与层级 + 多端规则 + 交付契约）
**产出**：`design-system/<项目slug>/`

> **动手前必须完整读 `$(resolve_skill ui-ux-pro-max)/references/prototype-delivery.md`** ——
> 那份是跨宿主唯一权威契约，本文件只给流程口径与门禁，两边不一致时**以契约为准**。
> 与 `dev-master` 的阶段 6 是**同一件事、同一个技能、同一个落盘根**，只是真源不同（见下）。

**目标**：把阶段5 的需求文档变成可点、可交互的设计稿，用于评审与对齐——**不是代码**。
要真出代码是 `dev-master` 的阶段 7，本流程不做。

**前置（缺件处理与契约同一口径，不要另写一套）**：

| 现状 | 处理 |
| --- | --- |
| PRD + SRS 都有 | 可启动 |
| 只有 PRD | 先走 `req-doc` **Step F** 转 SRS；用户**原话**要求「跳过 SRS 直接出设计稿」才允许只用 PRD，并在索引页注明 |
| 只有 SRS | 先 `pm-prd-spec` 出 PRD——**设计稿以 PRD 为主真源**，没 PRD 就没有页面清单与文案依据 |
| 只有 SRS，且项目走的是 `dev-master` 研发流程（没有产品侧 PRD 链路） | **允许以 SRS 为唯一真源出稿**（契约缺件表已开此豁免），索引页注明「无 PRD，页面清单与文案取自 SRS」。**不要为此去跑 `pm-prd-spec`**——研发流程里没有这一环，硬等 PRD 会把阶段 6 卡死 |
| 两个都没有 | 不要凭空造页面：先 `pm-prd-spec` 再 `req-doc` |

**输入**：`SPEC_SOURCE`（PRD 路径为主）+ SRS 全文（补规格细节）+ Step 0 问题4 的产品类型（决定出哪张墙）

**真源口径**：**本阶段以 PRD 为主**——页面清单、区块顺序、字段与枚举、文案原文、交互与状态都取 PRD，
SRS 只在 PRD 未写明时补规格细节（校验边界、状态机、接口约束）。两份冲突时**取 PRD**，
并在标注面板写明「取 PRD x.y.z（SRS 3.5.x 表述不同）」。
> 这条**只限设计稿**。`page-generator` 等七个研发技能的规格真源仍是 SRS，两者不冲突。
> 「取 PRD」是**动手改稿**，不是补一条标注就算完。

**交付模式**：继承 Step 0 所选 `DELIVERY_MODE`；**严格**档逐页确认，标准/快速批量不逐页问。

### 6.1 出稿

三张 iframe 预览墙，**只按画布尺寸分，不按形态分**：

| 墙 | 画布 | 收哪些形态 |
| --- | --- | --- |
| 移动墙 | 393×852 | APP / H5 / 小程序**共用一张**，卡片按形态分组（组头写形态 + PRD 章节号） |
| 官网墙 | 1280×900 | 企业官网 |
| 后台墙 | 1440×900 | Web 运营管理系统 |

点预览卡进全屏；**墙内不注入工具条**，需求标注开关与「重置演示进度」只在全屏页右下角。
**不做出稿帧**——所有状态与分支靠真实操作在流程里走到，产物里出现 `data-setframe` 即不合格。
到不了的状态说明流程缺了一环（少入口 / 少演示数据 / 少分支），**补流程，不补开关**。

另交两份文档：`FLOWS.md`（流程清单）、`HANDOFF.md`（工程师对接清单八节 + `tokens.json`）；
覆盖 ≥2 端时再加 `CONSISTENCY.md`。

**标注面板是内建的**，逐条列该页规则并标 `PRD x.y.z` / `SRS 3.5.x` 出处——
**走这条路不需要另调 `annotation` 技能**（那个是标 `dev/code/` 真实代码的）。

### 6.2 闭环检查（出稿即入检，**不可省**）

上面只解决「交付形态对不对」，**设计稿能不能支撑业务流程跑通是另一件事**。
按 `../prototype-review.md` 跑四阶段并四方签字：产品流程映射 → 测试真人走查 → 异常边界 → 一致性。

**不要**把这一步省成「评审会上过一遍」：三种最常见的断点
（流程有页面无 / 页面有走不到 / 点得动没反应）**在演示里一个都看不出来**。

常见失败：PRD 只写了正常流，设计稿照着做，检查时才发现异常流整块没有——
**那是 PRD 的缺口，不是设计稿的**，回阶段5 补，不要在设计稿里编一套。

**输出**：`design-system/<项目slug>/` 下三张墙之一 + 各页 HTML + `FLOWS.md` + `HANDOFF.md` + `tokens.json`

**完成标志（门禁，三条缺一不可）**：
1. `FLOWS.md` 与 `HANDOFF.md` 齐（覆盖 ≥2 端再加 `CONSISTENCY.md`）
2. 契约的**四组**机检（死按钮与孤层 / 流程完整性 / 清单反查九条 / 页面闭环：死链·无入链·无出链）输出 OK，含 `grep -l 'data-setframe' design-system/*/*.html` **为空**——对应 `../prototype-review.md` 的 M1–M4，四项全为 0
3. `prototype-review.md` 四阶段检查跑完且**四方签字**

**未签字的设计稿不得作为下游（阶段7 测试用例、阶段8 操作手册、`dev-master`）的输入。**

**可跳过**：不需要可点原型做评审对齐，或设计另有团队。
跳过的代价见 `../tailoring.md` 跳过判据表——阶段7/8 只能靠 `SPEC_SOURCE` 的文字描述。
