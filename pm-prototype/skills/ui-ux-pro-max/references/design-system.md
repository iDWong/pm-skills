# 设计系统：品牌层与组件层的内容规格

本文件规定**设计系统本身要写到什么程度**——`MASTER.md` 必含哪些章节、`tokens.json` 怎么与之对应、
组件库要覆盖到哪些件。交付流程与产物结构见 `prototype-delivery.md`（那份是交付契约，本份是内容规格）；
多端适配与一致性审查见 `platform-rules.md`。

**一句话判据**：设计系统的每一项都要能被**代码直接消费**。写不进 `tokens.json` 的条目，说明还停在形容词阶段。

## 一 · 品牌层（`MASTER.md` 必含九节，缺一即不合格）

| # | 节 | 必须给到 | 常见欠交付 |
| --- | --- | --- | --- |
| 1 | 品牌色 | 主色 + **9 档色阶**（50…900）；主色须给 `hover / active / disabled / focus-ring` 四个派生值，写明派生规则（如 hover = 主色混黑 8%）| 只给一个主色，交互态让前端自己调，结果每人调得不一样 |
| 2 | 辅助色 | 2–3 个，写明**各自的使用场景与禁用场景**（辅助色不做主 CTA）| 给了一排色号没说什么时候用，最后全站乱用 |
| 3 | 语义色 | success / warning / error / info 四组，**每组含 主色 + 浅底 + 边框 + 文字** 四个值，浅深两档各一套 | 只给四个主色，浅底自己 opacity，深色档下对比度崩 |
| 4 | 字体家族 | 中文 / 英文 / 数字三条 fallback 链；**数字是否等宽**（表格与金额必须等宽）；非系统字体给文件与授权 | 只写「思源黑体」，不给 fallback，Windows 上掉成宋体 |
| 5 | 字阶 | 每级给 **字号 / 行高 / 字重 / 字间距 / 用途**，至少 7 级（H1–H4 + body + caption + micro）；行高用**倍数**不用 px | 只给字号，行高交给浏览器默认 |
| 6 | 间距 | 基数 **4pt**（移动端）/ **8pt**（Web），阶梯 4·8·12·16·24·32·48·64；写明**哪一档用于什么**（组件内边距 / 区块间距 / 页面边距）| 给了阶梯不给用法，实现出来疏密无规律 |
| 7 | 圆角与阴影 | 圆角至少 4 档（控件 / 卡片 / 弹层 / 全圆）；阴影每档写全 `x y blur spread color`，且**深色档单列一套**（深色下阴影要靠亮边而非黑影）| 深色档直接复用浅色阴影，等于没有层级 |
| 8 | 图标风格 | 线性还是面性、线宽（1.5 / 2px）、端点圆角、网格尺寸（24 基准）、**尺寸档 16/20/24/32**、来源与授权 | 混用两套图标库，线宽不一 |
| 9 | 插画与动效原则 | 插画：风格（扁平 / 等距 / 手绘）、主色用法、**空态与错误态各自的插画位**；动效：时长三档 + 缓动 + 进出场方向语义 + reduced-motion 降级 | 插画只在空态出现一次就再没规范；动效只写「流畅自然」 |

**九节全部要能映射到 `tokens.json` 的八组**（`color / type / space / radius / shadow / icon / motion / breakpoint`）。
映射不上的条目（如插画风格）留在 `MASTER.md` 散文里，但**必须写明它约束的是哪些页面元素**，否则无从检查。

## 二 · 组件层（30 件，分五类）

每件都要给：**变体 / 尺寸档 / 八态 / 交互行为 / 动效 / 复用还是新增**（八态与「真到得了」的判据见 `prototype-delivery.md` 反查第 1 条）。

| 类 | 组件 | 这一类的额外要求 |
| --- | --- | --- |
| **基础（8）** | Button · Input · Select · Checkbox · Radio · Switch · Tag · Badge | Button 至少 4 变体（primary / secondary / text / danger）× 3 尺寸；Input 必须含**前后缀、清除、计数、错误位**；Badge 要给**超量显示规则**（99+） |
| **导航（5）** | Navbar · TabBar · Sidebar · Breadcrumb · Steps | TabBar ≤5 项且**当前项有文字**；Sidebar 给折叠态与二级展开；Steps 给**失败步**与可点回退规则 |
| **数据（5）** | Table · List · Card · Statistic · Chart | Table 必须给**固定表头 / 固定首列 / 空列宽策略 / 行选中 / 排序三态**；Statistic 给**单位、千分位、涨跌色**；Chart 见 `quick-reference.md` 图表类 |
| **反馈（7）** | Toast · Modal · Drawer · Popover · Loading · Empty · Skeleton | 四类层的**关闭方式**照契约「弹窗与浮层」；Empty 必须**文案 + 插画 + 出路按钮**三件套；Skeleton 的骨架形状要与真实内容同构 |
| **业务（5）** | 登录 · 支付 · 上传 · 搜索 · 筛选 | 这五件是**组合件不是控件**：每件必须有**完整流程**（`FLOWS.md` 里各占一条），且成功与失败两条分支都走得到 |

**业务五件的最低流程要求**（这一块最容易只做「好天气」那一条）：

- **登录**：验证码 / 密码 / 三方三选一为主路径；给出**失败三态**（账号不存在 / 密码错 / 风控拦截）与**重试倒计时**。
- **支付**：收银台 → 支付中 → 成功 / 失败 / **超时未支付** / **用户取消**；失败要能**回到原消耗点**而不是首页。
- **上传**：选择 → 校验（类型 / 大小 / 数量）→ 进度 → 成功 / 失败重传 / 取消；**断点续传是否支持要写死**。
- **搜索**：历史 / 建议 / 结果 / **无结果（给建议词）**；触发规则写明（输入 N 位、防抖毫秒）。
- **筛选**：多条件组合 → **已选条件回显** → 重置；移动端给抽屉版、后台给行内版，**两者条件语义必须一致**。

## 三 · 令牌同步：`tokens.json` 是唯一源

各端**生成**而不是手抄，生成脚本随包走（`_src/`）：

| 端 | 产物 | 生成方式 |
| --- | --- | --- |
| Web / H5 / 官网 / 后台 | CSS 自定义属性 | `color.brand.500` → `--color-brand-500` |
| iOS | `Tokens.swift`（`Color` / `CGFloat` 常量）| 驼峰化 key，色值走 `Color(hex:)` |
| Android | `colors.xml` + Compose `Theme.kt` | 下划线化 key |
| HarmonyOS | `tokens.ets`（ArkTS 常量）| 同 iOS 的驼峰规则 |
| 小程序 | `tokens.wxss` / `tokens.acss` | 同 Web，变量名不变 |

**与 `brand` / `design-system` / `slides` 那套项目根 `assets/design-tokens.{json,css}` 的关系**（别让一个项目出现两份令牌）：

| 项目情况 | 令牌唯一源 |
| --- | --- |
| 走了设计稿链路（有 `design-system/<项目slug>/`） | **`design-system/<项目slug>/tokens.json`**；项目根那两份若需要，由它生成，不手维护 |
| 没走设计稿链路（纯品牌 / 幻灯片 / 单页场景） | 沿用项目根 `assets/design-tokens.{json,css}`，与本链路无关 |
| 两份都已存在 | **以 `design-system/<项目slug>/tokens.json` 为准**，另一份标注「由 tokens.json 生成」后重新生成一次 |

三条硬规则：

1. **改令牌只改 `MASTER.md` 与 `tokens.json`**，各端产物一律重跑脚本生成——手改任一端即刻产生漂移。
2. **一个值只有一个来源**。同一个品牌色不允许在 iOS 侧再写一遍十六进制，`grep` 得到两处即为缺陷。
3. **令牌改动要走一次多端走查**（清单见 `platform-rules.md` 第 9 节），因为同一个值在不同端的观感不同（深色档尤其）。

## 四 · 表面与材质层（Surface & Material）

设计系统不是只有色号和字号 —— **同一套令牌铺在不同表面上会是两个东西**。这一层定义「界面由什么材质构成、
层与层怎么叠、降级怎么走」。六项必须定义齐，缺任何一项都不算完整设计系统；
本技能自带一套**默认参考实现**（磨砂玻璃体系，见文末资源），项目可以换材质，但**不能不定义**。

### 4.1 产品表面：先认表面，再写 CSS

| 表面 | 视觉语言 | 材质基调 | 控件尺寸 |
| --- | --- | --- | --- |
| 移动端 App（`.t-app`） | 深浅双主题、强调色点睛、圆润触控控件 | 双层材质（面板 / 控件分层） | 触控 ≥44px |
| 公开官网（`.t-web`） | 与 App 共用令牌，编辑式排版 + 响应式栅格 | 固定 Chrome 跨越纹理画布时才上材质 | 等效可达触控目标 |
| 运营后台（`.t-admin`） | 浅色数据体系、状态语义色、高密度 | 紧凑单层材质 | 紧凑 32px |

**三种表面共用同一份令牌**，差的是密度、圆角与材质强度 —— 不要为后台另起一套色板。

### 4.2 材质规则（六条，换材质也要有等价答案）

1. **材质要有东西可糊**：模糊平色等于没模糊。画布需要高频纹理或柔光，且纹理**在材质层之后**，不影响文字对比度。
2. **承载文字的实心件必须不透明**：主按钮、危险按钮、选中 Chip、徽章、消息气泡显式 `backdrop-filter:none` —— 它们扛着 `--on-brand` 文字。
3. **面板与控件分层**：面板模糊强、控件模糊弱（参考实现 App/官网 22px / 10px，后台 16px / 8px）。**内层面板改实心**，不要嵌套大半径模糊。
4. **数据区优先可读**：表格单元格、状态色块、选中态一律实心；装饰性模糊不进信息密集区。
5. **材质走语义令牌**（`--glass-bg` / `--glass-ctl` / `--material-nav`），组件变体里**禁止硬编码 `rgba()`**；
   语义变体的特异性要低于基础规则（`.chip{}` 可以，`.t-app .chip{}` 会盖掉 `chip--danger`）。
6. **扁平降级仍要保留投影** —— 投影是层级分离机制，不是材质效果，关材质不等于关层级。

### 4.3 z 轴层级契约（全站一套，不许各页自定）

`内容 0 → 吸顶 10 → Chrome 16 → FAB 18 → 遮罩 39 → 半屏/弹窗 40 → Toast 60 → 设计稿工具条 80`

嵌套、实心豁免与组件角色见 `references/surface/layering.md`。

### 4.4 主题双档与密度档

浅色 / 深色**两档都是一等公民**：深色不是把背景调黑 —— 阴影换亮边、纹理由灰转白、图表色要重新验对比度。
密度至少给「标准 / 紧凑」两档，后台默认紧凑。两档下正文对比度都要 ≥4.5:1。

### 4.5 降级三级（令牌重映射，不是逐组件覆盖）

| 触发 | 处理 |
| --- | --- |
| 低端设备（按触控与核数分级） | 降材质强度或转实心，保留投影 |
| 系统「减少透明度 / 减少动效」 | 材质转实心、动效降为淡入 |
| 引擎不支持 `backdrop-filter` | `@supports not` 里整体退实底，**不留糊不掉的半透明** |

人工开关 `setGlass('off')` 必须存在且**关完无残留模糊**。实现见 `references/surface/degradation.md`、
`assets/surface/glass-tier.js`。

### 4.6 默认参考实现（本技能自带，可直接内联）

| 文件 | 用途 |
| --- | --- |
| `assets/surface/frosted.css` | 三种表面的材质层与后台紧凑映射 |
| `assets/surface/tokens.json` | 平台无关的材质 / 品牌 / 形态 / 密度 / 层级令牌 |
| `assets/surface/glass-tier.js` | 设备分级与 `setGlass()` 人工覆盖 |
| `assets/surface/spec-sheet.html` | 材质样例与降级开关，评审时拿它对齐 |
| `references/surface/{tokens,layering,degradation,pitfalls,kirakira-surfaces}.md` | 令牌数值 / 层级 / 降级 / 特异性与对比度审计 / 一套完整表面样例 |

设计稿外壳**内联**这些文件（零依赖铁律），路径用 `resolve_skill ui-ux-pro-max` 解析后取 `assets/surface/`，
**不要硬编码技能库根**。项目换材质时，替换的是这些文件的内容，4.1–4.5 六项规则不变。

## 五 · 命名约定

- 令牌：`<组>.<语义>.<档>`，用途名不用外观名——`color.danger.500` 不写 `color.red.500`（改配色时外观名全废）。
- 组件类名：`<组件>__<部件>--<变体>`，状态用属性不用类（`[data-state="loading"]`），便于机检。
- 图标：`icon-<语义>`，与 `assets/icons/<symbol-id>.svg` 同名。
- 页面：见 `prototype-delivery.md`「目录与命名」；平台变体后缀见 `platform-rules.md` 第 0 节。
