# 需登录站点的处理规范

> Agent **无法**代替用户在浏览器里完成扫码、验证码、SSO、二次验证等登录；`WebFetch` 通常也 **不带 Cookie/Session**，故登录后内页默认 **不可达**。本文件规定检测、降级与用户协作方式。

## 1. 识别「登录墙」

抓取 URL 后，出现以下任一即判定 **存在登录门禁**（可兼有）：

| 信号 | 示例 |
| --- | --- |
| 跳转到登录页 | `/login`、`/signin`、统一认证回调 |
| 页面文案 | 「请登录」「未授权」「会话已过期」 |
| HTTP/壳层 | 401/403 页、空白壳 + 仅登录表单 |
| 导航缺失 | 主导航链接存在但内页均跳回登录 |
| 用户事先说明 | 「这是内网/后台，要账号」 |

在盘点稿 **§1 输入与限制** 写明：`登录门禁：是`、可见范围（如「仅登录页 + 落地页」）。

## 2. 禁止事项

- **禁止**伪造或猜测登录后页面结构、字段、按钮文案  
- **禁止**向用户索要生产环境真实密码并在对话中明文保存；若必须登录，优先让用户 **自行导出** 可离线阅读的材料  
- **禁止**把 `[未访问]` 区域写进 PRD 验收标准  
- **禁止**因够不到内页就停住不问；须完成 **可达部分盘点** + **明确缺口清单** + **请用户选补救方案**

## 3. 推荐补救方案（按优先级）

探测到登录墙后，**用一段话说明限制**，并让用户 **择一或组合**（不要一次抛五个问题，先给推荐序）：

| 优先级 | 用户可提供 | Agent 动作 |
| --- | --- | --- |
| **A（推荐）** | **Axure / 原型 HTML 导出包** | 转 `axure-html-parse.md` 全流程；与公开页冲突时标来源 |
| **B** | **已登录状态下另存/导出的 HTML**（整站或关键页文件夹） | 放入工作区任意路径或 `web/`，按本地 HTML 盘点 |
| **C** | **关键内页截图 + 简短说明**（每屏：页面名、能点的操作、备注） | 写入盘点 §4，标注 `[来源：用户截图]` |
| **D** | **页面清单 + 口述/旧 PRD**（「登录后有订单列表、详情、导出…」） | 盘点 §6/§7 记为 `[来源：用户口述]`，PRD 用 `[待补充]` 标细节 |
| **E** | **测试账号** | 见 §4；仅当用户明确提供且环境允许时再尝试，失败则退回 B/C/D |
| **F（可选）** | **已配置浏览器类 MCP** | 见 §9；可自动填表登录、遍历内页、截图与 DOM 摘录 |

**不推荐**默认让用户只给账号密码——多数环境 Agent 仍无法维持会话，且存在安全风险。

## 3.1 用户手动登录后，Agent 能继续读线上链接吗？

**结论：不能自动「接力」你浏览器里的登录态。**

| 方式 | 是否共享登录态 | 说明 |
| --- | --- | --- |
| 你在 Chrome/Edge 里已登录 | ❌ | Agent 的 `WebFetch` **不携带**你浏览器的 Cookie / Session |
| 你再发同一个 URL 让 Agent 抓 | ❌ | 仍会落在登录页或 401，除非你改用下方「可继续」方案 |
| 登录后 **另存 HTML** 到工作区 | ✅ | Agent `Read` 本地文件，按 `web-site-inventory.md` 盘点 |
| 登录后 **截图** 发到对话 | ✅ | 标注 `[来源：用户截图]` |
| 登录后复制 **完整网页 HTML 源码** 存为 `.html` | ✅（部分） | SPA 可能只有壳；多页需每页各存一份 |
| 提供 **Axure 导出包** | ✅ | 与是否线上登录无关，优先推荐 |

**推荐协作流程（「手动登录 → 继续盘点」）：**

```text
1. 你在本机浏览器登录测试/预发环境
2. 逐个打开关键内页 →「另存为」完整网页（或单文件 HTML）
      或 截图 + 页面名称/可点操作说明
3. 保存到工作区，例如：imports/site-export/ 或 web/mirror/
4. @ 文件夹路径告诉 Agent：「已登录导出，请继续盘点」
5. Agent 合并第一轮公开区盘点 + 第二轮导出材料，更新 -原型盘点.md
```

**注意：**

- 单页应用（React/Vue 等）「另存为」常只剩空壳 → 优先整页截图，或让设计提供 Axure
- 动态列表、弹窗等多状态：每个状态一屏截图或分别导出
- 勿在对话中粘贴 Cookie / Token 让 Agent 抓站（安全风险大，且多数环境不支持）

若用户问「我登录好了，你现在去读吧」→ 先说明上表限制，再引导走 **另存 HTML / 截图 / Axure** 其一。

## 4. 测试账号（可选，次选）

仅当用户 **主动提供** 测试环境账号时：

1. 确认是 **测试/预发** 环境，非生产  
2. 说明：Agent 可能仍无法完成交互式登录（验证码、扫码、企业微信、U盾等）  
3. 可尝试一次抓取；若仍落在登录页 → **立即**改走 §3 方案 B/C/D，不反复索要密码  
4. 对话与盘点稿中 **不写明文密码**；必要时写「凭据由用户本地保管」

## 5. 分段盘点策略

不必等「全部页面齐」才出盘点稿。

```text
第一轮（立即可做）
  → 盘点公开区：登录/注册页、落地页、帮助中心、页脚链接等
  → 从登录页表单反推：账号类型、字段、第三方登录入口、错误提示（可见部分）
  → §7 列出「登录后不可见模块」清单（从导航占位、文案、用户提示推断的写 [推断]）

第二轮（用户补充材料后）
  → 合并 B/C/D 输入，更新 §2 站点图、§4 分页面、§5 动线
  → 请用户再次确认盘点

第三轮
  → 概念版 → 落地 PRD（缺口仍保留 [待补充]）
```

## 6. 盘点稿与 PRD 标注

| 标注 | 含义 |
| --- | --- |
| `[未访问-需登录]` | 链接或导航存在，内容未抓取 |
| `[来源：用户截图]` | 界面来自用户补图 |
| `[来源：用户口述]` | 结构来自说明，无 HTML 真源 |
| `[仅登录页可见]` | 从登录/注册页能确定的范围 |

PRD §5 中，登录后功能若无真源，只写 **功能目标 + 页面级占位 + [待补充] 字段/规则**，不写具体按钮文案冒充真源。

## 7. 向用户的标准说明（可复制）

> 这个链接需要登录，我目前只能可靠盘点 **登录页和公开页面**；**你在自己浏览器里登录后，我无法自动沿用该会话**去抓内页。  
> 建议任选一种方式继续：  
> 1）提供 Axure/原型 HTML 导出（最佳）  
> 2）你登录后把关键页面「另存为 HTML」放进项目，或发截图 + 页面说明  
> 3）列一下登录后有哪些模块，我先把结构写进盘点，细节标待补充  
> 你方便用哪种？

## 8. 与三视角诊断的衔接

登录墙后 **权限模型、角色差异、数据范围** 几乎总在 §7 缺口中——在补缺口阶段 **优先问**：

- 有哪些角色？各角色登录后菜单是否不同？  
- 本期 PRD 要覆盖哪个角色的主路径？  
- 登录方式：账号密码 / SSO / 手机号 / 仅内网？

## 9. 通过 MCP 浏览器自动化（可选扩展）

> **本资源包默认不内置 MCP**；若用户在 Cursor 中已接入浏览器类 MCP，可 **升级** 方案 E/F，但仍须遵守 §2 禁止事项。

### 9.1 能否实现「登录并提取」？

**可以部分实现**，取决于所接 MCP 的能力与用户环境：

| 能力 | 典型 MCP / 工具 | 对 prototype-to-prd 的价值 |
| --- | --- | --- |
| 打开 URL、等渲染、点选填表 | Playwright MCP、Puppeteer、browser-use | 测试环境 **账号密码登录** 后可抓内页 DOM / 截图 |
| 多页导航、点菜单 | 同上 | 自动遍历主导航，补全站点图 |
| 截图（含弹窗态） | 真实浏览器 MCP | 相当于方案 C，但可批量 |
| 导出 HTML / accessibility tree | 部分 MCP 提供 snapshot | 写入 `imports/mcp-export/` 再盘点 |
| **沿用用户已登录的 Chrome 配置** | 少数 MCP 支持 `userDataDir` / 连接已有浏览器 | 可接近「手动登录后续读」 |

**仍难或无法自动完成：**

- 短信/邮箱验证码、滑块、图形验证码  
- 企业微信 / 钉钉 / 飞书扫码、U 盾、硬件 Key  
- 复杂 SSO（Okta、Azure AD 多跳）— 常需 **人工在 MCP 弹出的浏览器里点一次**  
- 内网仅 VPN 可达 — MCP 进程也须在 VPN 内  

### 9.2 推荐 MCP 工作流（已配置时）

```text
1. 确认：仅测试/预发 URL；凭据不进 PRD、不写进仓库
2. 用 MCP 打开登录页 → 填账号密码（或暂停让用户完成 SSO/扫码）
3. 登录成功后：
   a. 对关键 URL 列表：snapshot / screenshot / 存 HTML 到 imports/mcp-export/
   b. 必要时点击展开菜单、Tab、弹窗后再截第二态
4. Agent Read 导出物 + 按 web-site-inventory.md 盘点
5. 盘点稿 §1 注明：[来源：MCP 浏览器抓取]、MCP 名称、抓取时间
6. 抓取失败 → 不猜内容，退回 §3 方案 A/B/C
```

### 9.3 Agent 执行规则（有 MCP 时）

- **优先**用 MCP 产出 **本地文件**（HTML/截图），再 `Read` 盘点——比纯对话里描述 DOM 更可靠  
- MCP 返回的 accessibility snapshot：提取导航、按钮、表单 label；动态数据标 `[抓取时示例数据]`  
- **禁止**把 Cookie/Token 写入 `docs/` 或提交 git  
- **禁止**对生产环境做未授权的自动化登录；默认仅测试环境  
- 用户未配置 MCP 时：**不要**假设有浏览器工具，仍走 §3.1 手动导出流程  

### 9.4 与用户沟通（可复制）

> 如果你已在 Cursor 里配置了 **Playwright / 浏览器类 MCP**，我可以在测试环境尝试自动打开页面、登录（简单账密）并截图或导出页面结构，再写盘点和 PRD。  
> 若有扫码、验证码或公司 SSO，可能仍需你在 MCP 打开的浏览器里 **手动完成一步**，之后我再继续抓取。  
> 没有 MCP 的话，仍建议 Axure 导出或你登录后另存 HTML/截图。

### 9.5 与本包其他能力的关系

| 场景 | 选用 |
| --- | --- |
| 静态公开页 | `WebFetch` 即可 |
| 需登录、无 MCP | §3 方案 A–D |
| 需登录、有 MCP | §9 工作流 |
| 仅要截图进操作手册 | 可参考 `pm-operation-manual/references/screenshot-guide.md` |
