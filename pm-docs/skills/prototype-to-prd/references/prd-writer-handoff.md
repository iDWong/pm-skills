# 盘点稿 → PRD 衔接规则

本技能产出 `-原型盘点.md` 后，**写作规范完全对齐** `prd-writer`；本文件只说明 **字段映射与逆向场景特例**。

## 1. 模式选择

| 情况 | 模式 |
| --- | --- |
| 仅有原型/站点，无 PRD | **prd-writer 模式 A**（概念版 → 落地版） |
| 有 PRD，用户要对照原型改进 | **模式 B/C**；盘点稿作为评审附件，不全量重写 |
| 用户只要盘点、不要 PRD | 停在 `-原型盘点.md`，不强行写 PRD |

## 2. 概念版字段映射

| 概念版章节 | 盘点稿来源 |
| --- | --- |
| 一句话定位 | §6 功能聚合 + 用户补充（商业目标） |
| 产品形态 | Axure 自适应视图 / 站点响应式 + 用户确认 |
| 目标用户 | §7 用户视角缺口（访谈后填） |
| 产品价值 | §7 商业视角 + 用户确认 |
| 核心功能方向 | §6 功能聚合表（🔴 项提炼为 3–7 条方向） |
| 不做什么 | 站点图有但未选入 MVP 的模块 + 用户边界 |
| 待确认问题 | §7 剩余项 |
| **已有输入摘要** | 链回 `-原型盘点.md`；列输入源路径/URL |

**概念版不得**复制整份 §4 分页面细节；保持「方向对齐」粒度。

## 3. 落地版字段映射

| PRD 章节 | 盘点稿来源 |
| --- | --- |
| §1 产品概述 | 概念版 |
| §2 场景 | 概念版用户 + §5 动线角色 |
| §3 动线 | §5 Mermaid 细化（补异常分支） |
| §4 功能清单 | §6 树状化；🔴🟡⚪ 与用户 MVP 对齐 |
| §4.1 线框 | 选 §4 中核心页 ASCII |
| §5.x 功能细节 | 对应 §4 分页面 + 交互表；补状态表、数据字段、文案 |

### §5 书写优先级

1. 原型 **注解 / data.js 明示** 的规则 → 直接写
2. 界面 **可见文案与字段** → 写入数据规范与界面文案
3. **行业惯例推断** → `[待补充]` 或「建议默认：…」并请用户确认
4. **后端逻辑、权限、计费** → 几乎始终 `[待补充]` + 影响范围

### MVP 闸门

与 `prd-template.md` 一致：默认只展开 🔴 的 §5.x。盘点稿中「优先级建议」列仅为初稿；**严格** 下写 §5 前口头确认 N 个 MVP；**标准/快速** 以 §4 功能树 🔴 为准，不另问。

## 4. 标注规范（贯穿 PRD）

| 标注 | 含义 |
| --- | --- |
| `[原型摘录]` | 来自 Axure/页面可见内容 |
| `[推断]` | 动线或规则推断，需确认 |
| `[待补充]` | 原型未覆盖，不写死 |
| `[原型未标明]` | 已查注解与 data.js 仍无 |

## 5. 自检补充项

在 `prd-writer/references/self-check.md` 之外，额外确认：

- [ ] 盘点稿路径已写入概念版摘要
- [ ] PRD §3/§4 与盘点 §5/§6 无矛盾（或矛盾已用户裁定）
- [ ] 无将 `[推断]` 写成确定验收标准
- [ ] Axure/站点未覆盖区域在 §7 或 `[待补充]` 中已声明
