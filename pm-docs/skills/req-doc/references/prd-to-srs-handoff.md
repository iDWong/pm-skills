# PRD → SRS 转写对照表

> Step F 执行前 **必须 Read 本文件**。  
> 输入：`prd/PRD/*-产品需求文档-V*.md`（及可选 `-概念版-V*.md`、`-原型盘点-V*.md`；旧命名 `*-PRD.md` 一并接受）。  
> 输出：`dev/SRS/{日期}-{项目}-SRS需求规格说明书-V1.0.md`

---

## 文首元数据（SRS 必填）

在 SRS「一、文档信息」表格后追加：

```markdown
> **文档类型**：SRS 需求规格说明书（研发真源）
> **来源 PRD**：`prd/PRD/{YYYYMMDD}-{客户名称}{项目名称}{形态}-产品需求文档-V{版本号}.md`
> **转写日期**：YYYY-MM-DD
> **转写说明**：由 req-doc Step F 自 PRD 展开；PRD 为产品探索真源，本 SRS 为研发实现真源。
```

## 两种上游 PRD，结构不同（**先判是哪一种再往下读**）

本对照表的 `§N` 编号来自 `prd-writer` / `prototype-to-prd` 的模板。**`pm-prd-spec` 出的 PRD 不是这个结构**，
硬按 `§4`「找功能树」会找不到，然后误判成「PRD 不合格」——实际只是结构不同。

| | `prd-writer` / `prototype-to-prd` | `pm-prd-spec` |
| --- | --- | --- |
| 组织方式 | §1–§8 固定编号，**按功能**组织 | 一级=功能域、二级=页面、三级=页面内小节，**按页面**组织 |
| 功能清单 | §4 树状 + 🔴🟡⚪ | **文首无总清单**；功能域与页面标题本身就是清单，Step 2 的页面清单表可作补充 |
| 优先级 | §4 的 🔴🟡⚪ | **通常没有**（上游 `pm-master` 阶段2/3 已排过优先级，PRD 不重复标） |
| 详细描述 | §5.x 每个功能一节 | 每个页面一节，内含固定小节序列（功能概述/筛选/展示/表单/危险操作/界面与交互规范） |
| 字段规格 | §5 数据规范表 | T1 筛选条件表 / T2 列表字段表 / T3 表单字段表，**分散在各页面** |

**`pm-prd-spec` 结构的映射按这张表走**（上面那张 §N 表对它只有最后五行适用）：

| PRD 位置 | SRS 章节 | 转写要点 |
| --- | --- | --- |
| 文档标题 + 版本记录 | 一、文档信息 | 形态后缀（后台管理/APP/H5/小程序/官网）决定 SRS 的端范围表述 |
| 一级标题（功能域） | **3.1 总体功能架构** + **3.2 需求功能清单** | 功能域→一级菜单，页面→二级菜单；**3.1 须补出菜单层级与路由**（PRD 常缺，见下） |
| 二级标题（页面）+ 各页「功能概述」的入口路径 | **3.3 页面功能清单** | 入口路径（`运营后台 → 会员管理 → 会员列表`）直接转为菜单路径与路由 |
| 各页 T1/T2/T3 字段表 | 对应 3.5.x 的筛选/列表/表单字段表 | 三要素（字段名称/说明/示例值）保留；**示例值不要删**，它是 6.1 数据字典取值范围的依据 |
| 各页 T4 交互与校验表 | 3.5.x 操作说明 + 操作反馈 | 四要素原样转；用户提示文案保留原文 |
| 各页 T5 枚举表 | **6.1 数据字典** | 枚举值 + 说明进字典；状态类枚举的判定口径一并带上 |
| 各页 T7/T8/T9 危险操作三表 | 3.5.x 边界与异常 | 二次确认文案原文保留；数据变化表转为后置条件；失败处理表转为异常分支 |
| 各页 T13 界面与交互规范 | 3.5.x 界面约束 | **只取规范内容，丢掉「依据」列**——那是 UX 检索来源，不属于 SRS |
| 附录A–E | 五、非功能需求 / 六、数据需求 / 文末待确认 | 附录D 非功能需求直接进五；附录C 数据时效进 6.x；附录E 待确认项转为 SRS 的遗留问题清单 |

**范围怎么定**（`pm-prd-spec` 的 PRD 没有 🔴 标记时）：

1. PRD 里有页面清单表且带优先级列 → 按它取；
2. 没有 → 读 `prd/planning/roadmap-*.md` 的 V1.0 范围；
3. 都没有 → **列出 PRD 里的全部功能域与页面，问用户一次「本期转写哪些」**，不要默认全量，
   也不要因为找不到 🔴 就中止。

## 章节映射

**下表的 `§N` 仅适用于 `prd-writer` / `prototype-to-prd` 结构**；`pm-prd-spec` 结构见上一节。
T14–T17 四行两种结构通用。

| PRD 章节 | SRS 章节 | 转写要点 |
| --- | --- | --- |
| §1 产品概述 | 二、项目概述（2.1–2.4） | 背景、目标、用户；去掉产品口号式表述，改为可验收目标 |
| §2 目标用户与场景 | 2.3 用户角色 / 2.4 使用场景 | 角色表 + 场景描述 |
| §3 核心用户动线 | 三、项目建设内容 业务流程（或附录流程图） | Mermaid 保留；复杂图调 `diagram-generator` |
| §4 功能清单（树 + 🔴🟡⚪） | **3.2** 需求功能清单 + **3.1** 菜单架构 | 🔴→V1.0/P0；🟡→P1；⚪→后续版本；**3.1 须写出菜单层级与路由** |
| §4.1 线框图 | 3.1 或各 3.5.x 布局说明 | ASCII 可保留为「页面布局说明」，**禁止**写成 CSS/组件名 |
| §5 功能详细描述 | **3.3** 页面功能清单 + **3.5.x** 功能详细设计 | 见下表「§5 → 3.5 展开规则」 |
| §5 数据规范 | **6.1** 数据字典 | 枚举、字段类型、长度 |
| §7 产品类型附录 | 五、非功能需求 / 三、相关章节 | 按 `product-type-appendix` 内容归类 |
| PRD 状态表 / 交互表 | 3.5.x 筛选/列表/表单/规则/边界 | UI 术语按 `prd-language.md` 替换 |
| **T14 业务对象状态机** | **2.4 业务流程图** + 各 3.5.x「状态与权限说明」 | 状态机表转为状态流转说明并配流程图；**「副作用」列拆进对应功能的操作说明**（数据变化进 3.5.x，通知进 T15 那一行）；**「此状态下不允许的操作」必须保留**，它是后端做状态校验的唯一依据 |
| **T15 通知与消息清单** | 各 3.5.x「操作反馈」+ **六、数据需求**（消息模板表） | 文案原文与变量 `{}` 原样保留，**不要改写成"提示用户"**；渠道、发送时机、可否关闭转为消息模板表字段；合并限流策略写进 5.1 性能需求 |
| **T16 外部依赖与降级** | **4.3 外部系统集成** + 5.3 可用性需求 | 逐项转为集成说明（系统、调用方式、失败影响、降级）；**「是否阻断主流程」为「是」的，必须在 5.3 写明熔断与告警要求**，这是 SRS 才有的技术约束 |
| **T17 权限矩阵** | **3.4 页面访问权限** + 2.5 业务角色定义 | 矩阵按行转写，粒度保持「功能·操作」不要退化成页面级；**角色名必须与 2.5 逐字一致**；「无权限的表现」（不渲染/置灰/拦截）转为 3.5.x 的界面约束 |

**MVP 范围**：默认只转写 PRD §4 中 **🔴 核心 / MVP / V1.0** 对应模块的 3.5.x；🟡⚪ 在 3.2 保留名称与优先级，不写完整 3.5，除非用户要求全量。

## §5 → 3.5 展开规则

每个 PRD `### 5.x 功能名称` 对应一个 SRS `### 3.5.x 功能名称`，须包含：

| PRD 内容块 | SRS 3.5.x 子节 |
| --- | --- |
| 功能描述、触发条件 | 功能概述 |
| 交互细节表 | 操作说明 + 操作反馈（成功/失败文案） |
| 状态清单 | 状态与权限说明 |
| 边界条件 | 边界与异常 |
| 数据规范字段 | 筛选字段表 / 列表字段表 / 表单字段表 |
| （PRD 常缺） | **须补全**：菜单路径、路由、数据源（业务模块名，非 `/api`） |

**禁止直抄**：PRD 中的 loading、toast、Modal、Skeleton、API 路径 → 按 `prd-language.md` 改写。

**盘点稿**：若存在 `-原型盘点-V*.md`，3.3 页面清单与 3.1 路由须与盘点 **页面列表** 交叉校验，冲突以 **PRD §4 MVP 范围** 为准并备注。

## Analyzer / Writer 模式

Step F 的 3.5.x 任务与 Step A 相同，但 analyzer 传入：

```text
MODE: from_prd
SOURCE_PATH: {PRD绝对路径}
SUPPLEMENT_PATHS: [{概念版}, {原型盘点}]  # 可选
```

req-analyzer 须额外输出：

- 自 PRD §4 推断的 **菜单树 + 路由**
- PRD §5 中 **[待补充]** 项清单（writer 保留占位，不编造）

## 转写前检查（Step F0）

| 项 | 不通过则 |
| --- | --- |
| PRD 文件存在且可读 | 中止，提示先 `prd-writer` |
| PRD 已通过 `prd-writer/references/self-check.md` 或用户确认定稿 | 提示先完善 PRD |
| **本期范围可确定**——`prd-writer` 结构看 §4 是否含至少 1 个 🔴/MVP 模块；`pm-prd-spec` 结构按上文「范围怎么定」三步走 | **两种结构都不满足时才提示补**；`pm-prd-spec` 的 PRD 没有 🔴 是正常的，**不得据此判为不合格** |
| 无更新中的 `[待补充]` 阻塞 MVP 模块 | 列出阻塞项，问用户补全或标为非 MVP |
