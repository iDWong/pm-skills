# PRD → SRS 真源门禁

> **本文件是库内权威副本**。原件是 Vibepm 资源包的 `.agents/rules/prd-to-srs-gate.md`，
> 而 `Documents/Claude/Product/.agents/` 已于 2026-09 前删除，14 个技能的引用全部悬空。
> 2026-09-10 依据 `page-generator` 步骤0、`req-doc` Step F、`pm-prd-spec` §441 里**已内联的规则**重建；
> §1–§2、§5 是原有规则的原样收拢，**§3 话术与 §4 豁免词是重建的**（原文已不可得），可按需调整措辞。

## §1 适用范围：哪些技能必须过这道门禁

以下技能**不得以 PRD（`prd/PRD/*.md`，旧路径 `docs/PRD/*.md`）为规格真源**，必须先有合格 SRS：

`page-generator`、`hld-design`、`lld-design`、`feature-list`、`annotation`、`delivery-plan`、`dev-fullstack-product`

> `dev-fullstack-product` 来自姊妹库 `dev-skills`；只装了 `pm-skills` 的话忽略它，其余六个不变。

理由：这七个技能读的是 SRS 的 **3.1 / 3.2 / 3.3 / 3.5.x** 章节结构（功能列表、数据、流程、字段级规格）。
PRD 的 §4 / §5 是产品视角的功能与体验描述，**颗粒度和字段完整性都不够**，拿它当真源会让下游产出缺字段、缺校验、缺状态机。

## §2 检测（进入技能主流程之前执行）

1. 按顺序 glob，取第一个命中：
   - `dev/SRS/*.md` ← **现行落点**
   - `docs/SRS/*.md`（旧路径，只读兼容）
   - `docs/01-需求与规划/*SRS*.md`（更旧的归档路径，只读兼容）
   - `**/*需求*说明书*.md`
2. **按内容角色校验**，不是死认章节号——下面三样缺任一即视为「无合格 SRS」：

   | 角色 | 这一节必须给出什么 |
   | --- | --- |
   | **功能架构／功能清单** | 系统有哪些功能模块，成体系不是散列 |
   | **页面清单** | 有哪些页面／路由，与功能对得上 |
   | **功能详细设计** | **字段级**规格：字段、类型、必填、校验、枚举、状态流转 |

   章节号按模板走，**不同模板编号不同**：

   | 模板 | 功能架构／清单 | 页面清单 | 功能详细设计 |
   | --- | --- | --- | --- |
   | `requirements-spec.md`（默认） | 3.1 / 3.2 | 3.3 | 3.5 |
   | `rs-servicesmart-contract.md` | 第 8 章 | 第 9 章 | 第 9 章下的字段表 |
   | 用户从 Word 提炼的模板 | 读文档目录自行定位 | 同左 | 同左 |

   **只按 3.1/3.3/3.5 找不到就判死，是错的**——servicesmart 模板的 3.1 是「术语、定义」，
   照号读会把术语表当功能架构，照号判会把一份合格 SRS 挡在门外。先看文档目录再定位。
3. 分支：
   - **有合格 SRS** → 登记 `SPEC_SOURCE=<该路径>`，进入主流程
   - **无合格 SRS 且存在** `prd/PRD/*.md`（或旧路径 `docs/PRD/*.md`、`docs/**/*-PRD.md`）→ 走 §3
   - **两者都无** → 提示先产出需求文档，路由 `req-doc`（要 SRS）或 `prd-writer`（先要 PRD）

**禁止**：把 PRD 的 §4/§5 当作上表三个角色读取；禁止静默跳过本门禁；禁止因为「没有 3.3 这个号」就判一份结构完整的 SRS 不合格。

## §3 标准话术（只有 PRD 时对用户说的话）

> 检测到 `<PRD 路径>`，但没有找到合格的 SRS（需含功能清单、页面清单、字段级功能详细设计三部分）。
>
> `<当前技能名>` 读的是 SRS 的字段级规格，直接用 PRD 会缺字段、缺校验规则、缺状态流转，
> 产出的东西开发拿不走。
>
> 建议先转写：**`req-doc` Step F** 会按 `prd-to-srs-handoff.md` 的对照表把 PRD 的 §4/§5
> 展开成 SRS 的功能清单／页面清单／字段级详细设计，通常比重写快很多。
>
> 要现在转写吗？（或者你明确接受降级，我就按 PRD 的 §4/§5 先做一版，产出会标注 `⚠ 降级模式`）

**说完中止当前技能**，等用户答复。不要一边说着门禁一边继续跑。

## §4 降级豁免词

用户消息命中以下任一，视为**明确接受降级**，可跳过 SRS 直接读 PRD §4/§5：

| 类型 | 表述 |
|---|---|
| 直接授权 | 「接受降级」「降级模式」「就用 PRD」「不转 SRS」「先不写 SRS」 |
| 明知代价 | 「知道会缺字段」「先出个大概」「后面再补 SRS」 |
| 时间压力 + 明确指令 | 「来不及了，直接用 PRD 做」（**单纯说"急"不算**，必须带明确指令） |

**不算豁免的**：「快一点」「简单点」「先做吧」——这些是速度偏好，不是接受降级。
遇到这类表述仍按 §3 走一遍，只是话术可以压缩成两行。

降级后**必须**：产出文首标注 `⚠ 降级模式：来源 PRD <路径>`，并在末尾列出「因缺 SRS 而未能确定的项」。

## §5 与流程的关系

`pm-master` 13 阶段流程里，本门禁是**阶段5 → 阶段6／移交 `dev-master` 的关口**
（注意：**阶段6 现在是「界面设计稿」不是「前端原型」**，产品链不出代码；设计稿同样要求 PRD+SRS 都有）：

- 阶段5（Step 0 问题5）选 **SRS** → 走 `req-doc`，天然满足门禁
- 选 **PRD** 或 **先 PRD 后 SRS** → 进阶段6，或交给 `dev-master`（含直接调 `page-generator` 等七技能）前，必须过 5C（`req-doc` Step F）
- 裁剪含阶段6、或用户跑完阶段5 打算接研发时，Step 0 问题5 **默认选 SRS**，避免用户在不知情下卡在这里

细则见 `pm-master/references/stages/s5-spec.md` 的 5.0 分支表。
