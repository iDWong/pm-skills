# Profile：小程序

微信 / 支付宝 / 抖音小程序。有 tabBar、授权按钮、订阅消息、包体积与页面栈限制、平台审核。

## 附加铁律

- **N1 授权必须写清"按钮触发"**：小程序的手机号、用户信息等敏感授权**只能由用户点击按钮触发**，不能在页面加载时静默调用。写清哪个按钮、按钮文案、拒绝后怎么办。
- **N2 订阅消息必须写清时机与条数**：一次性订阅每次只能发一条，必须在用户操作时申请。写清在哪个动作后弹订阅、订阅哪个模板、用户拒绝后的兜底触达方式。
- **N3 平台差异必须显式声明**：多平台上线时，凡是能力有差异的地方（支付、定位、分享、登录）都要写 `微信 | 支付宝 | 抖音` 三列对照，不能只写"调用平台能力"。
- **N4 审核合规前置**：涉及虚拟支付、医疗、金融、教育、直播的功能，必须在文档里写明类目资质要求与平台限制——iOS 端虚拟支付被禁是最常见的上线前爆雷。

## 页面类型（只用这七种）

`tabBar 页`、`列表页`、`详情页`、`表单页`、`结果页`、`个人中心`、`浮层（modal / action-sheet / toast / 半屏弹窗）`

## 信息架构写法

```
小程序（主包 ≤ 2MB）
├── tabBar（≤5 项）
│   ├── pages/index/index          首页        [tabBar 页]
│   ├── pages/category/index       分类        [列表页]
│   └── pages/mine/index           我的        [个人中心]
└── 分包 subpackage-order/（按需加载）
    ├── pages/detail/index         商品详情    [详情页] → 规格选择（半屏弹窗）
    ├── pages/confirm/index        下单确认    [表单页]
    └── pages/result/index         支付结果    [结果页]
```

入口写法：`页面入口：小程序 → 首页tabBar → 商品卡片点击 → 商品详情页`

**必写的平台硬约束**：页面栈最多 10 层（超出后 `navigateTo` 失败，必须用 `redirectTo` 或 `reLaunch`）；主包 ≤ 2MB、总包 ≤ 20MB（微信）；tabBar ≤ 5 项；右上角胶囊按钮区域不可覆盖。

## 需求澄清补充

| 问题 | 影响 |
| --- | --- |
| 上哪些平台？微信/支付宝/抖音？ | 决定是否要平台差异对照表 |
| 主体类目是什么？有没有虚拟支付/医疗/金融内容？ | 决定审核合规章节，可能直接否决方案 |
| 需要手机号授权吗？什么时候要？ | 决定授权章节 |
| 需要订阅消息吗？推什么？ | 决定订阅消息章节 |
| 有没有从公众号/朋友圈/扫码进入的场景？ | 决定场景值与来源分流 |
| 分享出去别人看到什么？ | 决定分享配置章节 |

## 形态特有全局章节

- **登录与授权**：`授权项 | 触发按钮 | 按钮文案 | 说明文案 | 拒绝后降级 | 二次引导`；静默登录（`wx.login` 换 openid）与显式授权分开写
- **订阅消息**：`模板 | 类型（一次性/长期） | 申请时机 | 发送条件 | 文案变量 | 用户拒绝后的兜底`
- **分享与场景值**：分享卡片标题/图片/路径、朋友圈分享、场景值枚举与来源分流逻辑
- **包体积与分包**：主包放什么、分包怎么切、哪些资源走 CDN
- **审核合规**：类目资质、平台限制（如 iOS 端虚拟支付）、敏感词、诱导分享红线
- **平台差异总表**：多平台上线时汇总所有能力差异

> **与开篇第 6 章「全局通用规则」的分工**：第 6 章定**全形态通用**的九类规则
> （权限/加载/网络异常/一致性/埋点/错误日志/安全隐私/缓存限流/文案），写一次；
> 本节只写**这个形态特有**的部分，不要把第 6 章的内容再抄一遍。
> 与第 6 章重叠的条目，在本节写「见 6.x」即可。

## UX 检索

规则集读 `$UIUX/references/pro-rules.md` **加** `quick-reference.md`。设计系统参数：`--variance 4 --motion 4 --density 5`。

| 章节 | 查询 |
| --- | --- |
| 列表 | `"pull to refresh infinite scroll list" --domain ux` |
| 表单 | `"form labels helper text required" --domain ux` |
| 状态 | `"empty state loading skeleton feedback" --domain ux` |
| 导航 | `"bottom navigation back button" --domain ux` |
| 触控 | `"touch target size spacing" --domain ux` |

注意：小程序的原生组件（video / map / canvas / textarea）**层级永远最高**，会盖住普通浮层。凡是页面里有原生组件又要弹浮层的，必须在「界面与交互规范」里写明用 `cover-view` 或先隐藏原生组件。
