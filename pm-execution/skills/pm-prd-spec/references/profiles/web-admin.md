# Profile：Web 运营管理系统

后台 / 中台 / 运营侧。左侧菜单树、列表页、筛选、批量操作、权限隔离。

## 附加铁律

- **A1 权限先行**：每个页面写清"谁能看见""看得见多少数据"。数据可见范围不是技术细节，是产品决策——不同权限的人看到的"总量"本身就不同。
- **A2 危险操作必有四件套**：二次确认原文 + 交互规则表 + 数据变化表 + 失败处理表。缺一件测试就写不全用例。
- **A3 列表页三件套不可省**：分页规则、导出规则（无导出也要明说）、操作列逐条行为说明。

## 页面类型（只用这七种）

`登录页`、`看板页`、`列表页`、`表单弹窗`、`详情页/详情弹窗`、`指标分析页`、`只读日志页`

可直接复制的模板见 `../module-templates.md`（模板 1–8）。

## 信息架构写法

```
管理后台
├── 仪表盘                    [看板页]
├── 系统设置
│   ├── 用户管理              [列表页 + 新建弹窗 + 重置密码弹窗]
│   └── 系统日志
│       └── 操作日志          [只读日志页]
└── 数据统计
    └── 运营日报              [指标分析页]
```

入口写法：`功能入口：管理后台 → 系统设置 → 用户管理 → 【新建用户】`

## 需求澄清补充

| 问题 | 影响 |
| --- | --- |
| 是否需要角色权限？菜单级还是按钮级？ | 决定是否要权限模型章节 |
| 同层数据是否共享（有菜单权限就看全部，还是只看自己创建的）？ | 决定数据可见范围规则 |
| 每张表大概多少数据？导出量级？ | 决定分页策略与导出同步/异步 |
| 哪些操作需要审批流？ | 决定是否要状态机章节 |

## 形态特有全局章节

- **权限模型**：`用户 → 角色 → 权限` 三层表 + 数据可见范围 + 菜单权限树父子勾选联动
- **操作日志与操作类型枚举**：`操作类型 | 说明 | 典型场景`
- **安全防护机制**：防暴力破解、Token 有效期、单点登录、闲置超时
- **错误提示规范**：全局文案表
- **多语言版本**（如有）：切换入口放哪、覆盖范围（通常只覆盖界面固定文本，不含用户产生的内容）、文案配置形式（建议 Excel/配置文件，便于后续手动补语种）、未翻译兜底
- **产品边界**：逐条列出明确排除的功能，每条写明「后续版本迭代」。写法与判据见 `../doc-style.md`「开篇三节」③。
  **这一节放在文档开篇，不是附录**——评审时它是被问得最多的一节。
