# Profile：移动端 H5

浏览器里打开的移动网页：微信内置浏览器、Safari、App WebView。活动页、落地页、分享链接。

## 附加铁律

- **H1 运行容器必须写清**：同一个 H5 在微信内置浏览器、Safari、App WebView 里能力完全不同（能否唤起 App、能否调起支付、能否获取定位）。开头就写清目标容器和各容器的降级方案。
- **H2 首屏性能是需求不是优化**：H5 的用户来自点击分享链接，首屏慢一秒流失一大截。必须写明首屏加载时间预算、骨架屏策略、图片格式与懒加载范围。
- **H3 分享配置必须写原文**：分享卡片的标题、描述、缩略图、落地路径，四项都要给成品内容，不能写"配置分享信息"。
- **H4 返回与历史栈必须写清**：微信的左上角返回、Android 物理返回键、页面内返回按钮三者行为是否一致；多步表单中途返回是否保留已填内容。

## 页面类型（只用这六种）

`落地页`、`活动页`、`表单页`、`结果页`、`列表页`、`浮层（弹窗 / 底部面板 / Toast）`

## 信息架构写法

H5 通常是**流程**而不是树，用流程图表达：

```
分享卡片 / 短信 / 二维码 / 广告位
    ▼
【落地页】
    ├─ 未登录 → 点击【立即参与】→ 手机号登录页 → 回到落地页原位置
    └─ 已登录 → 继续
    ▼
【活动页】填写信息
    ├─ 活动未开始 → 提示"活动将于 9 月 10 日 10:00 开始，先收藏一下吧"
    ├─ 活动已结束 → 提示"活动已结束，感谢参与"→ 引导至【结果页】
    └─ 进行中 → 继续
    ▼
【表单页】提交
    ├─ 校验失败 → 就近提示，焦点落到首个错误字段
    └─ 通过 → 提交
    ▼
【结果页】→ 分享给好友 / 唤起 App / 下载引导
```

入口写法：`页面入口：微信分享卡片 → 落地页 → 【立即参与】→ 活动页`

## 需求澄清补充

| 问题 | 影响 |
| --- | --- |
| 主要在哪个容器里打开？微信内 / 外部浏览器 / 自家 App？ | 决定容器差异表，影响能否用微信支付、能否唤起 App |
| 流量从哪来？分享 / 短信 / 广告 / 二维码？ | 决定 UTM 参数与来源分流 |
| 要不要唤起或下载 App？ | 决定唤端章节（微信内无法直接唤端，只能引导浏览器打开） |
| 需要登录吗？用什么方式（手机号/微信授权）？ | 决定登录态传递方案 |
| 活动有时间窗口和名额限制吗？ | 决定活动状态机 |
| 首屏性能预算是多少？ | 决定加载策略 |

## 形态特有全局章节

- **运行容器与降级**：各容器能力对照总表
- **分享配置**：`分享场景（好友/朋友圈） | 标题 | 描述 | 缩略图 | 落地路径`，全部给原文
- **登录态**：登录方式、token 怎么传、跨页面怎么保持、失效后怎么办
- **唤端与下载引导**：唤起成功/失败/未安装三条路径的分别表现
- **活动状态机**（活动类必写）：`状态 | 时间条件 | 页面表现 | 按钮文案 | 可操作性`
- **首屏性能预算**：首屏时间目标、图片格式与尺寸、懒加载范围、骨架屏
- **埋点与渠道追踪**：UTM 参数规范、关键转化节点
- **多语言版本**（如有）：由外部传参还是页面内切换（本版固定传参时要写明「接口预留该字段、不提供切换入口」）、文案配置形式、未翻译兜底
- **产品边界**：逐条列出明确排除的功能，每条写明「后续版本迭代」。写法与判据见 `../doc-style.md`「开篇三节」③。
  **这一节放在文档开篇，不是附录**——评审时它是被问得最多的一节。

## UX 检索

规则集读 `$UIUX/references/pro-rules.md` **加** `quick-reference.md`。设计系统参数：`--variance 6 --motion 5 --density 4`。

| 章节 | 查询 |
| --- | --- |
| 首屏性能 | `"image lazy load cls layout shift" --domain ux` |
| 区块顺序与 CTA | `"hero cta conversion" --domain landing` |
| 表单 | `"lead capture form validation" --domain ux` |
| 状态 | `"empty state loading skeleton feedback" --domain ux` |
| 返回 | `"gesture conflict swipe back" --domain ux` |

**必写的性能约束**（检索命中）：首屏以下图片懒加载（`ux/Performance/Lazy Loading`）；图片用 WebP 并给合适尺寸（`ux/Performance/Image Optimization`，High）；字体加载用 fallback 预留空间避免抖动（`ux/Typography/Font Loading`）。

## 原型图
