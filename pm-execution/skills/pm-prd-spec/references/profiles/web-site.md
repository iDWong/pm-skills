# Profile：Web 官网

对外展示与获客。Hero、功能介绍、定价、客户案例、博客、留资表单。目标是转化，不是功能。

## 附加铁律

- **W1 每个页面必须写清转化目标**：这个页面希望访客做什么（留资 / 注册 / 下载 / 联系销售 / 继续浏览下一页）？主 CTA 是哪个、出现几次、放在哪。没有转化目标的官网页面等于装饰。
- **W2 SEO 是需求不是优化**：每个页面必须写 title、meta description、H1、URL 路径、结构化数据类型。这几项由产品定，不是等开发随手填。
- **W3 内容可维护性必须声明**：哪些内容走 CMS 后台可改、哪些是硬编码。写死的内容以后每改一个字都要发版——这个决策必须在文档里显式做出。
- **W4 区块顺序要有依据**：Hero → 什么 → 什么 → CTA 的顺序不能拍脑袋，用 `--domain landing` 检索出的 Section Order 作为依据，在文档里标出来源。

## 页面类型（只用这七种）

`首页（Hero 型）`、`功能介绍页`、`定价页`、`客户案例页`、`关于/联系页`、`内容列表页（博客/资讯）`、`内容详情页`

## 标准小节序列

| # | 小节 | 标准表头 / 内容 |
| --- | --- | --- |
| 1 | 功能概述 | 无表：页面入口（导航路径）、页面定位、**转化目标**、目标访客 |
| 2 | 区块顺序 | `序号 \| 区块 \| 内容要点 \| CTA \| 依据`，自上而下；依据列写检索命中的 Section Order |
| 3 | 内容字段 | `字段名称 \| 字段说明 \| 示例值 \| 是否走 CMS` |
| 4 | CTA 设计 | `CTA 文案 \| 位置 \| 样式（主/次） \| 点击行为 \| 转化事件名` |
| 5 | 表单与校验 | 有留资表单时：字段表 + 四要素校验表 + 提交后表现 |
| 6 | SEO 配置 | `项 \| 内容`：title、meta description、H1、URL、OG 图、结构化数据 |
| 7 | 响应式表现 | `断点 \| 布局变化 \| 隐藏/折叠的内容` |
| 8 | 界面与交互规范 | `维度 \| 规范 \| 依据` |
| 9 | **边界条件** | 五问逐条答（内容空/超长、网络异常、无权限、并发、格式不符）；不适用要写明「不适用（理由）」。见 `../doc-style.md`「边界条件五问」 |
| 10 | **验收标准** | 2–5 条可勾选，句式「做了什么 → 看到什么」，至少一条失败路径。见 `../doc-style.md`「验收标准」 |

**原型图不单独成节**：以 `**页面原型图**` 粗体块 + 图 + 图注嵌在小节 1「功能概述」末尾；浮层各一张，紧随所属页面。

## 信息架构写法

导航结构 + 页面列表：

```
官网
├── 顶部导航
│   ├── 产品        → 功能介绍页（下拉：功能A / 功能B / 功能C）
│   ├── 解决方案    → 行业方案页 ×3
│   ├── 定价        → 定价页
│   ├── 客户案例    → 案例列表页 → 案例详情页
│   └── 资源        → 博客列表页 → 博客详情页
├── 导航右侧 CTA   → 【免费试用】（主）/【联系销售】（次）
└── 页脚
    ├── 关于我们 / 联系我们 / 加入我们
    └── 隐私政策 / 服务条款 / 备案号
```

入口写法：`页面入口：官网 → 顶部导航【产品】→ 功能介绍页`

## 需求澄清补充

| 问题 | 影响 |
| --- | --- |
| 主转化目标是什么？留资 / 注册 / 下载 / 打电话？ | 决定 CTA 设计与页面结构 |
| 目标访客是谁？决策者还是使用者？ | 决定内容深度与话术 |
| 线索提交后流向哪里（CRM / 邮件 / 企微）？谁跟进？ | 决定表单字段与提交后流程 |
| 要做 SEO 吗？目标关键词是什么？ | 决定 SEO 章节详略与 URL 结构 |
| 需要多语言吗？ | 决定多语言章节与内容量翻倍 |
| 哪些内容会经常改（案例、价格、博客）？ | 决定 CMS 范围 |
| 有品牌规范吗（VI、字体、色板）？ | 决定设计系统是沿用还是新生成 |

## 形态特有全局章节

- **SEO 总表**：全站 `页面 | URL | title | description | H1 | 优先级`，加 sitemap、robots、canonical 规则
- **转化漏斗与埋点**：`环节 | 页面 | 事件名 | 触发条件`，从落地到留资全链路
- **渠道追踪**：UTM 参数规范、来源如何带进线索
- **线索流转**：表单提交后的去向、通知谁、SLA
- **CMS 可维护范围**：`模块 | 是否可后台编辑 | 编辑角色`
- **多语言版本**（如有）：语言切换方式、URL 结构（子域/子路径）、未翻译内容的兜底
- **性能与 Core Web Vitals**：LCP / CLS / INP 目标值
- **合规**：Cookie 同意、隐私政策、备案信息展示位置
- **产品边界**：逐条列出明确排除的功能，每条写明「后续版本迭代」。写法与判据见 `../doc-style.md`「开篇三节」③。
  **这一节放在文档开篇，不是附录**——评审时它是被问得最多的一节。

## UX 检索

规则集读 `$UIUX/references/quick-reference.md`。设计系统参数：`--variance 7 --motion 6 --density 3`。

**区块顺序必须先检索再定**：

```bash
python3 "$UIUX/scripts/search.py" "hero pricing testimonials cta" --domain landing -n 3
```

`landing` domain 返回的字段直接对应本 profile 的小节：`Section Order` → 区块顺序表、`Primary CTA Placement` → CTA 设计表、`Color Strategy` → 界面与交互规范、`Conversion Optimization` → 各区块的内容要点。

| 章节 | 查询 |
| --- | --- |
| 区块顺序 | `"hero pricing testimonials cta" --domain landing` |
| 风格基调 | `"saas marketing website" --domain product`、`--domain style` |
| 首屏性能 | `"image lazy load cls layout shift" --domain ux` |
| 表单 | `"form labels helper text required" --domain ux` |
| 导航 | `"sidebar navigation breadcrumb deep link" --domain ux` |
| 动效 | `"scroll reveal parallax" --domain gsap` |

**注意**：官网的 `--variance 7` 意味着允许大胆布局，但**无障碍不打折**——对比度 4.5:1、键盘可达、焦点可见、reduced motion 这四项在任何 variance 下都是硬要求。轮播/自动滚动必须提供暂停控件并在 focus/hover/reduced-motion 时停止。

## 原型图

画布 1440 宽（桌面主视图），长度按区块数定，常见 1440×2400+。用 `sitepage()` 组件画顶部导航条 + 页脚。首屏折线用虚线标出并注明"首屏折线（1440×900）"。移动端断点差异大的页面（如定价表转卡片流）额外画一张 375 宽的对照图。
