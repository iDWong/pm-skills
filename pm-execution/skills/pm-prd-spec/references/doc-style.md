# 文体规范（全形态通用）

本文件的表头、文案范式与禁用写法**五种形态通用**。形态特有的小节序列与章节见 `profiles/<形态>.md`。

本文件定义 PM-PRD-Spec 的**全部标准表头、文案范式与禁用写法**。Step 4 动笔前通读一遍；写作过程中按需回查。

---

## 一、文档骨架

文档标题（H1）取文件名去掉日期与版本号的部分，即 `{客户名称}{项目名称}{形态}产品需求文档`；形态五选一：后台管理 / APP / H5 / 小程序 / 官网。落盘路径与版本号规则见 `SKILL.md` Step 7。

```
{客户名称}{项目名称}{形态}产品需求文档

目录（自动生成，导出 Word 时保留）

1 登录功能
  1.1 功能概述
  1.2 登录界面UI设计
  1.3 登录流程
  1.4 错误提示规范
  1.5 安全防护机制
      1.5.1 防暴力破解策略
      1.5.2 会话管理
2 仪表盘
  2.1 汇总统计
  2.2 趋势统计
3 系统设置
  3.1 用户管理
      3.1.1 功能概述
      3.1.2 数据筛选
      3.1.3 数据展示
      3.1.4 新建用户
      3.1.5 界面与交互规范
  3.2 角色管理
  3.3 系统日志
4 {业务域一}
5 {业务域二}
6 数据统计
7 订单管理
附录A 全局错误提示规范
附录B 操作类型枚举
附录C 数据时效与统计口径
附录D 非功能需求
附录E 待确认项清单
```

**层级规则**
- 一级 = 功能域（对应左侧一级菜单）
- 二级 = 页面（对应二级菜单或独立页面）
- 三级 = 页面内的固定小节（功能概述 / 数据筛选 / 数据展示 / 新建X / 界面与交互规范）
- 每个页面的「功能概述」小节末尾必须挂一张**页面原型图**，弹窗单独一张（见 `wireframe.md`）

**两样东西别混称**（同一交付包里会同时出现，评审时问过不止一次）：

| 东西 | 正式叫法 | 在哪 | 谁出 |
| --- | --- | --- | --- |
| PRD 正文里那张静态图 | **页面原型图** | 嵌在每个页面「功能概述」小节末尾 | 本技能（Step 4） |
| 可点、可交互的独立 HTML | **UI/UX设计稿**（简称设计稿） | `design-system/<项目slug>/`（三张预览墙 + 全屏页） | `ui-ux-pro-max`（Step 8） |

正文、图注、README、交付说明与产物页面文案都按这张表用词。触发词（全技能统一）：**设计稿 / 高保真原型 / 可点原型 / 交互原型 / 预览墙**——用户说其中任意一个都是指后者，照旧识别，不用纠正用户的说法。
- 最深到三级；再往下用加粗小标题，不要出现四级编号

**标题写法**：中文标题**以冒号结尾**（`功能概述：`、`数据筛选：`、`新建用户：`），与参考文档一致。

## 二、十七种标准表格

写到对应内容时，**直接套用下列表头，不要自创列名**。

### T1 筛选条件表

| 筛选项 | 控件类型 | 默认条件 | 输入提示文字 | 输入规则 |
| --- | --- | --- | --- | --- |
| 用户名称 | 单行输入框 | 无 | 请输入用户名 | 限 20 个字符以内，只能是字母或字母+数字，禁止特殊符号 |
| 用户状态 | 下拉选择框 | 全部 | 无 | 可选择：全部 / 启用 / 停用 |
| 创建时间 | 日期区间选择器 | 默认选中近 7 天 | — | 最大范围可选 30 天 |

- 控件类型只用这批词：`单行输入框`、`多行文本域`、`数字输入框`、`数字区间输入框`、`下拉选择框`、`多选下拉`、`搜索+下拉`、`单选按钮`、`复选框`、`开关`、`日期选择器`、`日期区间选择器`、`时间范围选择器`、`树形结构`、`文件上传`、`只读展示`。
- 无默认值写 `无`，不适用写 `—`。
- 精确/模糊搜索必须写明：`支持按剧名模糊搜索`、`精确搜索`。

### T2 列表字段表

| 字段名称 | 字段说明 | 示例值 |
| --- | --- | --- |
| 日志ID | 全局唯一编号 | 20260902001234 |
| 操作时间 | 精确到毫秒的时间戳 | 2026-09-02 14:32:15 |
| 用户 | 被操作用户的昵称 + UID（点击可跳转至用户画像） | 追剧小能手 (U-100886) |
| 操作 | 可进行的操作 | — |

- 三列是下限。需要区分展示样式时加第四列 `展示规则`（`可复制`、`标签样式`、`YYYY-MM-DD HH:mm`、`数字，保留两位小数`）。
- **操作列在表格里只列名字，具体行为在表格下方逐条展开**：

```
点击【查看详情】后打开：用户画像详情。
点击【编辑标签】后打开标签选择弹窗，可选择所有已创建好的标签，支持多选。
点击【删除】后打开二次确认弹窗（文案见下）。
```

- 表格后必须补两句：分页规则、导出规则。
  - `数据超过 10 条记录后进行分页。`
  - `数据可根据查询条件导出 .xlsx 文件。`（无导出就写"本页不提供导出"）

### T3 表单字段表

| 字段名称 | 控件类型 | 是否必填 | 输入提示文字 | 输入提示/规则 |
| --- | --- | --- | --- | --- |
| 用户名称 | 单行输入框 | 是 | 请输入用户名 | 限 8–20 个字符；只能是字母或字母+数字，禁止特殊符号 |
| 用户密码 | 单行输入框 | 是 | 请输入用户密码 | 暗文显示，可切换明文；限 8–20 个字符；只能是字母或字母+数字 |
| 角色名称 | 下拉选择框 | 是 | 请选择角色 | 可选择所有已创建的角色 |
| 用户状态 | 单选按钮 | 是 | 无 | 启用 / 停用二选一，默认选中：启用 |

- 是否必填只写 `是` / `否`。
- 条件显示的字段必须写清条件：`仅当上传方式="上传视频"时显示`。
- 文件类字段写清格式与体积：`mp4，≤100MB，拖动或点击上传`。

### T4 交互与校验表

| 触发时机 | 校验规则 | 用户提示 | 处理方式 |
| --- | --- | --- | --- |
| 输入等级名称时 | 同一平台内名称是否重复 | 名称已存在，请重新输入 | 阻止提交，高亮字段 |
| 输入门槛金额时 | 是否 ≤ 上一等级门槛 | 最低消费门槛必须高于上一等级 | 阻止提交，高亮字段 |
| 点击【确认创建】时 | 所有必填字段是否已填 | 聚焦到第一个未填字段，显示对应提示 | 阻止提交 |

- 处理方式用词：`阻止提交，高亮字段`、`阻止提交`、`仅提示不阻断`、`按钮置灰`、`自动纠正为合法值`。
- **每个表单至少 3 条校验**：唯一性、字符/数值边界、必填聚合校验。

### T5 枚举表

| 显示名称 | 说明 |
| --- | --- |
| 支付未到账 | 用户已扣款但平台未收到回调，最常见场景 |
| 客服补偿 | 因平台体验问题（如卡顿、音画不同步）给用户的补偿 |
| 其他 | 需在备注中说明具体原因 |

带场景的枚举加第三列 `典型场景`：

| 操作类型 | 说明 | 典型场景 |
| --- | --- | --- |
| 新增 | 创建新资源 | 新建剧集 / 新建用户 |
| 审核 | 审核通过 | 剧集审核通过 |
| 导出 | 导出数据 | 导出订单报表、用户列表 |

- 有 `其他` 选项的枚举，必须同时在表单表里写"选择'其他'时备注强制必填"。
- 枚举会随业务变化时标注：`（随实际功能有所调整）`。

### T6 错误提示规范表

| 错误场景 | 前端提示文案 | 提示位置 | 后端日志记录 |
| --- | --- | --- | --- |
| 账号为空 | 请输入账号 | 输入框下方 | 不记录 |
| 账号不存在或密码错误 | 账号或密码错误，请重新输入 | 弹窗提示 | 记录"登录失败（账号/密码错误）" |
| 系统内部错误 | 系统繁忙，请稍后再试 | 弹窗提示 | 记录详细错误堆栈 |

- 提示位置只用：`输入框下方`、`弹窗提示`、`顶部 Toast`、`表格内联`、`页面级空态`。
- 安全相关错误一律**模糊提示**，并在说明中写明原因：`（统一模糊提示，不暴露具体原因）`。

### T7 交互规则表（危险操作）

| 规则 | 说明 |
| --- | --- |
| 仅可退一次 | 已退款的订单，【发起退款】按钮置灰或隐藏，不可重复操作 |
| 金额校验 | 退款金额 > 实付金额 → 前端拦截，提示"退款金额不能超过实付金额" |
| 二次确认弹窗 | 点击【确认退款】后，弹出二次确认弹窗，展示完整摘要：即将对订单【WX202609011432001】发起退款 ¥0.99，并回收该剧集权益。确认继续吗？ |
| 实时生效 | 确认后用户端立即获得权限（无需重启 APP），通过 WebSocket 推送权益变更 |

### T8 数据变化表

| 数据项 | 变化说明 |
| --- | --- |
| 订单状态 | 从 支付成功 变为 已退款 |
| 累计消费金额 | 扣减退款金额 |
| 已购剧集总数 | 如果该剧仅通过此订单获得，退款后不再拥有该剧权益 → -1 |
| 操作日志 | 记录操作人、操作时间、用户、订单号、退款金额、退款原因、渠道退款流水号 |

**任何写操作都要有这张表。** 开发靠它判断要改哪些字段、要不要发消息。

| 失败场景 | 系统行为 |

### T14 业务对象状态机表（有生命周期的对象必写）

**什么时候要写**：对象有状态且状态会流转——订单、审核、退款、工单、提现、活动、内容发布。
**什么时候不用写**：纯 CRUD 对象（会员、标签、配置项），只有"存在/删除"不算状态机。

一个对象一张表，**放在该对象所属功能域的开头**（不是塞进某个页面），因为状态流转横跨多个页面：

| 当前状态 | 触发事件 | 谁能触发 | 新状态 | 副作用（数据变化 / 通知） | 此状态下不允许的操作 |
| --- | --- | --- | --- | --- | --- |
| 待审核 | 提交审核 | 创作者 | 审核中 | 锁定内容不可编辑；站内信通知审核员 | 编辑、删除 |
| 审核中 | 审核通过 | 审核员 | 已发布 | 写入发布时间；推送通知创作者；进入推荐池 | 撤回（需先下架） |
| 审核中 | 审核驳回 | 审核员 | 已驳回 | 记录驳回理由（必填）；站内信通知创作者 | — |
| 已驳回 | 重新提交 | 创作者 | 审核中 | 清空上次驳回理由；**每日最多重提 3 次** | — |
| 已发布 | 下架 | 审核员 / 运营 | 已下架 | 移出推荐池；已购用户仍可访问 | 编辑 |
| 已下架 | 重新上架 | 运营 | 已发布 | 重新进入推荐池 | — |

- **最后一列是这张表的价值所在，也是最常漏的**：只写"能做什么"，开发就会默认"没写的都能做"。
  「已取消的订单能不能退款」「驳回后能不能直接删」这类问题，全靠这一列回答。
- **每个状态都要能走到，也要能走出**（终态除外）。写完自查：有没有进得去出不来的状态？
  有没有哪个状态没有任何事件指向它（死状态）？
- 终态明确标注：`已完成`、`已取消`、`已过期` 这类写明"终态，不再流转"。
- 事件命名用**业务动作**（提交审核、驳回、下架），不用 `status=2` 这类实现细节。
- 有超时自动流转的写清条件：`待支付 | 超时 30 分钟未支付 | 系统 | 已取消 | 释放库存；短信通知`。
- 表下方配一张状态流转图（`diagram-generator` 出），**图与表必须一致**，改了表就要重出图。

### T15 通知与消息清单（有对外触达就要写）

**什么时候要写**：系统会主动给人发消息——短信、站内信、推送、邮件、企业微信/钉钉。
**什么时候不用写**：纯内部工具且无任何对外触达。

**后台形态尤其容易漏这张表**：后台的操作（调整积分、停用账号、审核通过）触发的是**发给 C 端用户**的
消息，不写就等于让开发自己决定发不发、发什么。

| 触发事件 | 渠道 | 接收人 | 文案原文 | 发送时机 | 用户可否关闭 |
| --- | --- | --- | --- | --- | --- |
| 运营调整积分 | 短信 | 被调整的会员 | 【星云】您的积分有变动：+500，当前可用 12,980。如有疑问请联系客服。 | 调整成功后实时 | 否（账户安全类） |
| 账号被停用 | 站内信 + 短信 | 被停用的会员 | 您的账号已被停用，如需恢复请联系客服 400-xxx-xxxx。 | 停用成功后实时 | 否 |
| 内容审核驳回 | 站内信 | 创作者 | 您的作品《{标题}》未通过审核，原因：{驳回理由}。修改后可重新提交。 | 审核完成后实时 | 否 |
| 每日数据日报 | 邮件 | 订阅的运营 | 见邮件模板 `daily-report` | 每日 09:00 | **是**，在个人设置中关闭 |

- **文案给原文**，变量用 `{}` 标明来源（`{标题}`、`{驳回理由}`）。短信要标明签名与是否计费。
- **账户安全与资金类不可关闭**，营销与提醒类必须可关闭——这是合规要求，不是产品偏好。
- 高频事件写明**合并与限流**策略：`同一会员 1 小时内多次调整，合并为一条汇总短信`。
- 与形态特有章节的分工：`mobile-app` 的「推送通知」、`miniprogram` 的「订阅消息」写的是
  **端上怎么收**（权限、模板、点击落地页）；本表写的是**业务上何时发、发给谁、发什么**。
  两者都有时，本表是真源，端上章节只补收取侧的细节。

### T16 外部依赖与降级表（依赖三方就要写）

**什么时候要写**：功能依赖本系统之外的服务——支付、短信、推送、OCR、地图、实名认证、对象存储、
企业微信、第三方登录。
**什么时候不用写**：全部能力自建且无外部调用。

T9 失败处理表是**页面级**的（这个操作失败了怎么办），这张是**项目级**的（我们依赖了谁、挂了怎么办）：

| 依赖系统 | 用在哪些功能 | 调用方式 | 失败影响 | 降级方案 | 是否阻断主流程 |
| --- | --- | --- | --- | --- | --- |
| 短信网关（阿里云） | 积分变动通知、停用通知、验证码 | 异步队列 | 用户收不到通知 | 失败重试 3 次；仍失败转站内信并记录告警 | 否 |
| 支付网关（微信支付） | 会员充值 | 同步 + 回调 | 无法充值 | 无降级，展示「支付暂不可用，请稍后再试」 | **是** |
| 对象存储（OSS） | 头像、内容图片上传 | 同步 | 无法上传图片 | 上传失败保留草稿，提示稍后重试 | 否 |
| 实名认证（三方） | 创作者入驻 | 同步 | 无法完成入驻 | 转人工审核通道，24 小时内处理 | 否 |

- **「是否阻断主流程」这一列决定技术方案**：阻断的必须做熔断与监控告警，不阻断的可以异步重试。
- 有 SLA 或配额限制的写明：`短信日发送上限 10 万条，超出需提前报备`。
- **评审时技术方一定会问这张表**，没有就会当场卡住：「支付走哪家」「短信通道是谁」「挂了怎么办」。

### T17 权限矩阵（多角色项目必写）

**什么时候要写**：系统有 2 个以上角色。
**什么时候不用写**：单角色系统。

T10 权限模型表写的是**概念三层**（用户→角色→权限），开发建权限表时需要的是**可直接落库的矩阵**：

| 功能 / 操作 | 超级管理员 | 运营主管 | 客服 | 财务 |
| --- | --- | --- | --- | --- |
| 会员列表 · 查看 | ✅ | ✅ | ✅ | ✅ |
| 会员列表 · 导出 | ✅ | ✅ | ❌ | ✅ |
| 会员 · 停用/启用 | ✅ | ✅ | ❌ | ❌ |
| 积分调整 · 单次 ≤5,000 | ✅ | ✅ | ✅ | ❌ |
| 积分调整 · 单次 >5,000 | ✅ | ✅ | ❌ | ❌ |
| 操作日志 · 查看 | ✅ | ✅ | ❌ | ✅ |
| 账号管理 | ✅ | ❌ | ❌ | ❌ |

- **行的粒度是"功能 · 操作"，不是"页面"**——同一页面里查看与导出往往不同权限，写成页面级开发没法做。
- **带阈值的权限要单独成行**（如"单次 ≤5,000 / >5,000"），这类最容易被写成一行然后做丢。
- **无权限的表现必须写明**：整页拦截 / 菜单不显示 / 按钮不渲染 / 按钮置灰 + tooltip，四选一，
  逐行或统一说明。**"不渲染"与"置灰"是两种产品决策**：置灰会暴露功能存在，敏感操作用不渲染。
- 矩阵里的角色名必须与 T10、菜单权限树、`4.x 角色定义`**逐字一致**，否则会出现没人认领的格子。
- 角色多于 6 个时按功能域拆成多张表，不要横向滚动到看不清。

## 三、文案范式

### 入口路径（形式随形态，规则统一）

| 形态 | 写法 |
| --- | --- |
| Web 运营管理系统 | `功能入口：管理后台 → 系统设置 → 用户管理 → 【新建用户】` |
| 移动端 APP | `页面入口：App → 首页Tab → 内容卡片点击 → 内容详情页` |
| 小程序 | `页面入口：小程序 → 首页tabBar → 商品卡片点击 → 商品详情页` |
| 移动端 H5 | `页面入口：微信分享卡片 → 落地页 → 【立即参与】→ 活动页` |
| Web 官网 | `页面入口：官网 → 顶部导航【产品】→ 功能介绍页` |

- 分隔符固定用 `→`（全角箭头，两侧留空格）。
- 按钮名用 `【】`：`【新建用户】`、`【查看详情】`、`【确认补发】`。
- 弹窗打开方式要写：`点击【新建用户】后，从屏幕中间弹出表单窗口。`

### 二次确认弹窗

必须写成**完整可上线的整句**，包含：动作 + 对象（带 `【】`）+ 后果 + 反问。

```
即将对【架空历史】分类进行删除，删除后将影响所有已关联的剧集。确认继续吗？
即将为用户【追剧小能手】补发【《前夫跪求复婚》全集】，确认继续吗？
即将对订单【WX202609011432001】发起退款 ¥0.99，并回收该剧集权益。确认继续吗？
```

### 状态与操作的联动

```
禁用/启用：状态为启用时，按钮显示"禁用"，点击后状态变更为禁用，反之一样。需要二次确认提示弹窗。
【退款】只有支付成功状态的订单可见，并可以操作；操作后修改订单状态为：已退款。
【补单】只有非支付成功状态的订单可见，并可以操作；操作后修改订单状态为：支付成功。
```

### 指标卡九行式

每个指标卡固定写这九行（不适用的写"不适用"，不要整行省略）：

```
总收入：
  定义：平台累计到昨日的收入金额（所有已支付订单金额总和，不含退款）
  时间口径：累计，不受顶部时间筛选器影响
  计算方式：所有已支付订单的金额总和 - 退款总金额
  主数字格式：金额格式，保留两位小数，千位分隔符（如 125,680.50）
  环比对比：环比上月（自然月同期对比）
  环比计算：（本月累计收入 - 上月累计收入）/ 上月累计收入 × 100%
  环比展示：正增长绿色↑，负增长红色↓，单位百分比
  展示文案：环比上月 +18%
  特殊处理：若上个月无数据，显示"—"
```

**受筛选器影响的指标**额外补一段不同范围的环比口径：

```
  不同时间范围的环比口径：
    昨日 → 较前日
    近 7 天 → 较上一个 7 天（不含今天）
    近 30 天 → 较上一个 30 天（不含今天）
    自定义 → 较上一个等长周期
```

**百分比类指标的环比是"百分点差值"，不是百分比变化率**——必须写清楚，这是最常见的口径事故。

### 图表规格

```
收入趋势：
  图表类型：折线图 + 面积图效果（渐变填充）
  数据维度：每日收入金额
  横轴：日期（按时间筛选器范围，不含今日）
  纵轴：收入金额
  数据点：每天 1 个数值，用圆点标记
  面积填充：折线下方渐变半透明填充，增强视觉层次
  交互：鼠标悬停显示具体数值（日期 + 金额）
  统计口径：已支付订单金额 - 当日退款
  时间范围：受顶部时间筛选器控制
  数据说明：展示筛选范围内每一天的收入金额
  空数据表现：无数据时显示空态插图 + 文案"当前筛选条件下暂无数据"
```

### 数据时效声明

涉及统计的页面开头必须写：

```
今日数据不统计，实时查询消耗过大，数据采用定时器跑批后存入数据库。
数据采用每日 02:00 进行统计。
```

## 四、禁用写法

| 禁用 | 改成 |
| --- | --- |
| "提示错误信息" / "给出相应提示" | 写出原文：提示"账号或密码错误，请重新输入" |
| 示例值写 "xxx" / "字符串" / "某某" | 写具体假数据：`COMP20260902001`、`2026-09-02 10:15:23` |
| "支持筛选" | 列出 T1 筛选条件表 |
| "字段若干" / "包含基本信息" | 列出 T2/T3 字段表，一个不漏 |
| "做必要的校验" | 列出 T4 交互与校验表 |
| "展示图表" | 按图表规格九行写 |
| "环比展示" 而不说口径 | 写出环比计算公式和百分点 vs 百分比 |
| 用散段落罗列多个同类项 | 转成表格 |
| 写技术实现（用 Redis 缓存、加索引） | 只写"要求列表首屏 ≤ 2 秒"，实现交给 `lld-design` |
| 用 emoji 当结构图标 | 用文字或说明 SVG 图标族 |
| 页面写完不给 UX 规范段 | 补 T13 |
| 页面写完不配原型图 | 补一张，弹窗单独一张（见 `wireframe.md`） |
| 原型图 PNG 用中文文件名 | 改成纯 ASCII，否则 Word 导出静默丢图 |

## 五、语言风格

- 全中文，专业但不啰嗦；一句话说清一件事。
- 数字、英文、代码与中文之间不强制加空格，但同一份文档内保持一致。
- 金额统一写 `¥` 或 `（元）` 后缀，二选一贯穿全文。
- 时间格式统一：日期 `2026-09-02`，日期时间 `2026-09-02 14:32:15`，列表展示可用 `2026-09-02 10:15`。
- 枚举分隔符统一用 ` / `：`正常 / 已冻结 / 已注销`。
- 范围符号用 `≥ ≤ >` 而不是 `大于等于`。
