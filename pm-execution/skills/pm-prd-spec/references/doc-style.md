# 文体规范（全形态通用）

本文件的表头、文案范式与禁用写法**五种形态通用**。形态特有的小节序列与章节见 `profiles/<形态>.md`。

本文件定义 PM-PRD-Spec 的**全部标准表头、文案范式与禁用写法**。Step 4 动笔前通读一遍；写作过程中按需回查。

---

## 一、文档骨架

文档标题（H1）取文件名去掉日期与版本号的部分，即 `{客户名称}{项目名称}{形态}产品需求文档`；形态五选一：后台管理 / APP / H5 / 小程序 / 官网。落盘路径与版本号规则见 `SKILL.md` Step 7。

**层级规则**
- 一级 = 功能域（对应左侧一级菜单）
- 二级 = 页面（对应二级菜单或独立页面）
- 三级 = 页面内的固定小节（功能概述 / 数据筛选 / 数据展示 / 新建X / 界面与交互规范）
- 每个页面的「功能概述」小节末尾必须挂一张**页面原型图**，弹窗单独一张（见 `wireframe.md`）

**两样东西别混称**（同一交付包里会同时出现，评审时问过不止一次）：

| 东西 | 正式叫法 | 在哪 | 谁出 |
| --- | --- | --- | --- |
| PRD 正文里那张静态图 | **页面原型图** | 嵌在每个页面「功能概述」小节末尾 | 本技能（Step 4） |
| 可点、可交互的独立 HTML | **UI/UX设计稿**（简称设计稿） | `design-system/<项目slug>/`（三张预览墙 + 全屏页） | `ui-ux-pro-max`（Step 8） |

正文、图注、README、交付说明与产物页面文案都按这张表用词。触发词（全技能统一）：**设计稿 / 高保真原型 / 可点原型 / 交互原型 / 预览墙**——用户说其中任意一个都是指后者，照旧识别，不用纠正用户的说法。
- 最深到三级；再往下用加粗小标题，不要出现四级编号

### 开篇六章（功能域之前，缺一不可）

功能正文只回答「这一页怎么做」，开篇六章回答的是评审第一轮必问的六件事：
**为什么做、凭什么赢、边界在哪、给谁用、先做哪些、全局怎么统一**。

**上游有产出就摘录，不要在 PRD 里重做。** 本技能在 `pm-master` 流程里位于阶段5，
前面的阶段已经产出了调研、画像、优先级、路线图——开篇六章的一半内容是**摘录 + 给出处**，
只有上游缺件时才在这里补，并标注「本文档补写，未经专项调研」。

| 章 | 写什么 | 上游真源（有就摘录） |
| --- | --- | --- |
| 1 项目背景与目标 | 痛点表 + 三档目标 + 愿景一句话 + 形态选型 | 阶段0 `prd/research/market-research-*.md` |
| 2 产品定位 | 商业价值 / 盈利模式 / 差异化定位 | 阶段-2 `prd/strategy/strategy.md`、阶段-1 `gtm.md` |
| 3 产品边界 | 功能/技术/合规三类边界 + 不包含功能 + 核心用户动线 | 阶段4 `prd/planning/requirements.md` |
| 4 用户角色与画像 | 角色权限定义 + 画像摘要 + 典型场景 | 阶段1 `prd/research/user-persona-*.md` |
| 5 功能清单与优先级 | 🔴🟡⚪ 树 + 优先级含义 + 章节映射 | 阶段2 `feature-priority-*.md`、阶段3 `roadmap-*.md` |
| 6 全局通用规则 | 九类全局规则，见下 | 无上游，本章原创 |

**1 项目背景与目标**

- **1.1 行业背景**用痛点表，不用散文：`痛点领域 | 具体问题 | 业务影响`。
  三列的意义是逼出因果——只写"效率低"没用，要写清它导致什么业务后果。
- **1.2 产品目标**分**短期 / 中期 / 长期**三档，每档带时间范围（如「MVP 阶段，1–2 个月」），
  每条目标必须是**可验收的结果**（"实现内容管理、互动管理、数据分析的基础能力闭环"），
  不是方向（"提升用户体验"）。短期那档要与第 5 章的 🔴 对得上。
- **1.3 产品愿景**一句话，可以有感情，但要具体到领域。
- **1.4 产品形态**用 `维度 | 当前选型 | 选择理由` 表，维度至少含：各端形态、嵌入能力、阶段策略。
  **"选择理由"列不能省**——它替你挡住半年后"当初为什么不做 App"的追问。

**2 产品定位**

- 商业价值 3–5 条，每条指向一个可感知的收益方。
- 盈利模式用 `模式 | 说明 | 优先级 | 阶段` 表；**产品不涉及商业化时整节写「本期不涉及商业化」**，不要删掉这一节。
- 差异化定位写与对标产品的关键差异，**一条差异配一个事实**，不写"更好用"。
- 深度的战略推演（画布、五力、定价模型）不在 PRD 里做 → `pm-strategy-frameworks`。

**3 产品边界**（六章里最该认真写的一章）

| 节 | 表头 / 写法 | 漏了会怎样 |
| --- | --- | --- |
| 3.1 核心功能边界 | `一级模块 | 二级模块 | 说明` | 开发按自己的理解划模块，与第 5 章清单对不上 |
| 3.2 技术边界 | `层级 | 技术选型 | 说明`，层级含前端各端、后端、存储、第三方能力 | UX 规范与组件选型悬空，评审时才发现技术不支持 |
| 3.3 合规边界 | 资质要求、数据合规（个人信息、支付）、平台规则红线 | 上线前才发现缺资质，整块功能返工 |
| 3.4 不包含功能 | `不包含功能 | 原因 | 评估方向` | **只列"不做"不够**，没写原因就会被反复提案；没写评估方向，需求方以为是永久否决 |
| 3.5 核心用户动线 | Mermaid `flowchart TD`，**主流程 + 每个判断点的异常分支** | 只有页面清单没有动线，评审看不出流程是否闭环 |

**3.5 的动线必须画到异常分支**：连接失败→重试、支付失败→重试、验证失败→回登录，
这些回环是流程闭环的证据。只画一条happy path 的动线等于没画。一份 PRD 至少一张总动线；
多端产品**每端一张**。

**4 用户角色与用户画像**

- **4.1 用户角色定义**用 `角色 | 类型 | 描述 | 核心权限`，按层级分组（平台级 / 账号级 / 用户端）。
  这张表是第 6.1 节 RBAC 矩阵的行来源，**两处的角色名必须逐字一致**。
- 4.2 画像从阶段1 摘录，PRD 里只留与功能决策相关的部分。
- 4.3 典型使用场景 2–3 个，每个写全：谁 / 什么情况 / 做什么 / 期望什么结果。

**5 功能清单与优先级**

- **5.1 功能清单**用树状 + 优先级标记，标到**二级模块**（不是只标顶层）：

```
产品名称
├── 🔴 用户端（H5）
│   ├── 🔴 用户系统
│   │   ├── 注册与登录
│   │   └── 个人中心
│   └── 🟡 创作者中心
└── 🔴 运营系统（WEB）
```

- **5.2 优先级说明**必须成表 `优先级 | 含义 | 说明`，把三档的**判据**写死：

| 优先级 | 含义 | 说明 |
| --- | --- | --- |
| 🔴 核心 | MVP 阶段必须完成，确保核心功能闭环 | 不完成则无法上线 |
| 🟡 重要 | 功能完善阶段完成 | 可在 MVP+ 阶段迭代 |
| ⚪ 未来 | 高级功能阶段完成 | 长期规划 |

- **5.3 功能清单与章节映射**给 `功能模块 | 对应章节`——清单与正文章节一一对上，漏写的当场看得出来。
- **范围闸门**：动笔写功能正文前先算一句给用户——「本期共 N 个 🔴 模块，先只展开这些；
  🟡/⚪ 只在清单留名，是否下一版再写？」**得到答复再动笔**。🟡/⚪ 的模块在正文里不展开、不配原型图。
- 优先级来源冲突（路线图 vs 用户说明）时**列出冲突请用户裁定**，不要自己挑一个。

**6 全局通用规则**（九类，全形态通用；写一次，正文各页不再重复）

| 节 | 内容 | 判据 |
| --- | --- | --- |
| 6.1 权限控制 | 用户状态与访问范围（未登录/已登录/已认证各能看到什么）+ **RBAC 角色权限矩阵**（角色 × 功能，格子写 ✓/✗/部分） | 角色名与 4.1 逐字一致 |
| 6.2 加载与刷新 | 首屏加载、下拉刷新、上拉加载、骨架屏用在哪 | 每种加载态指明使用场景 |
| 6.3 网络异常处理 | `场景 | 处理方式`：首次加载失败 / 加载更多失败 / 提交失败 / 全局断网 / 第三方超时 | 每条给出**文案原文**与可行动项 |
| 6.3.1 输入校验全局规范 | `场景 | 校验规则 | UI反馈`：文本 trim、字数上限、粘贴超长、链接格式 | **字数口径要写死**（中文/英文/Emoji 统一按 1 字符计），否则前后端算不一样 |
| 6.3.2 媒体上传统一规范 | 格式白名单、体积上限、尺寸限制、失败重试 | 与各页表单字段的文件规则一致 |
| 6.3.3 弱网环境行为 | 超时阈值、重试次数、降级策略 | 给具体秒数与次数 |
| 6.4 数据一致性 | 多端同步、乐观锁、并发编辑、缓存与真值的关系 | 写明冲突时谁赢、用户看到什么 |
| 6.5 埋点统一规范 | 事件命名规则、公共参数、上报时机 | 只写口径，方案转 `pm-tracking-spec-writer` |
| 6.6 错误处理与日志 | **错误码体系**（码段划分）+ 错误提示（用 T6）+ 日志记录规范 | 错误码分段要能一眼看出归属模块 |
| 6.7 安全与隐私 | 敏感数据脱敏、传输加密、越权防护、日志脱敏 | 与 3.3 合规边界呼应 |
| 6.8 缓存与限流 | 缓存策略（哪些缓存、多久）+ 限流策略（接口、频次、超限提示） | 给具体数值 |
| 6.9 文案规范 | 通用原则 + 终端用户文案清单 + **字段命名规范** + 多语言 | 字段命名规范决定前后端字段名，别省 |

**这一章与各页「界面与交互规范」的分工**：本章定**全局一次**（所有页面都适用的），
各页那张表给**该页特有的规范 + UX 检索依据**。同一条规则不要两处都写；
页面层只在偏离全局规则时说明「本页例外：…（原因）」。

**标题写法**：中文标题**以冒号结尾**（`功能概述：`、`数据筛选：`、`新建用户：`），与参考文档一致。

## 二、十六种标准表格

写到对应内容时，**直接套用下列表头，不要自创列名**。

### T1 筛选条件表

| 筛选项 | 控件类型 | 默认条件 | 输入提示文字 | 输入规则 |
| --- | --- | --- | --- | --- |
| 用户名称 | 单行输入框 | 无 | 请输入用户名 | 限 20 个字符以内，只能是字母或字母+数字，禁止特殊符号 |
| 用户状态 | 下拉选择框 | 全部 | 无 | 可选择：全部 / 启用 / 停用 |
| 创建时间 | 日期区间选择器 | 默认选中近 7 天 | — | 最大范围可选 30 天 |

- 控件类型只用这批词：`单行输入框`、`多行文本域`、`数字输入框`、`数字区间输入框`、`下拉选择框`、`多选下拉`、`搜索+下拉`、`单选按钮`、`复选框`、`开关`、`日期选择器`、`日期区间选择器`、`时间范围选择器`、`树形结构`、`文件上传`、`只读展示`。
- 无默认值写 `无`，不适用写 `—`。
- 精确/模糊搜索必须写明：`支持按剧名模糊搜索`、`精确搜索`。

### T2 列表字段表

| 字段名称 | 字段说明 | 示例值 |
| --- | --- | --- |
| 日志ID | 全局唯一编号 | 20260902001234 |
| 操作时间 | 精确到毫秒的时间戳 | 2026-09-02 14:32:15 |
| 用户 | 被操作用户的昵称 + UID（点击可跳转至用户画像） | 追剧小能手 (U-100886) |
| 操作 | 可进行的操作 | — |

- 三列是下限。需要区分展示样式时加第四列 `展示规则`（`可复制`、`标签样式`、`YYYY-MM-DD HH:mm`、`数字，保留两位小数`）。
- **操作列在表格里只列名字，具体行为在表格下方逐条展开**：

```
点击【查看详情】后打开：用户画像详情。
点击【编辑标签】后打开标签选择弹窗，可选择所有已创建好的标签，支持多选。
点击【删除】后打开二次确认弹窗（文案见下）。
```

- 表格后必须补两句：分页规则、导出规则。
  - `数据超过 10 条记录后进行分页。`
  - `数据可根据查询条件导出 .xlsx 文件。`（无导出就写"本页不提供导出"）

### T3 表单字段表

| 字段名称 | 控件类型 | 是否必填 | 输入提示文字 | 输入提示/规则 |
| --- | --- | --- | --- | --- |
| 用户名称 | 单行输入框 | 是 | 请输入用户名 | 限 8–20 个字符；只能是字母或字母+数字，禁止特殊符号 |
| 用户密码 | 单行输入框 | 是 | 请输入用户密码 | 暗文显示，可切换明文；限 8–20 个字符；只能是字母或字母+数字 |
| 角色名称 | 下拉选择框 | 是 | 请选择角色 | 可选择所有已创建的角色 |
| 用户状态 | 单选按钮 | 是 | 无 | 启用 / 停用二选一，默认选中：启用 |

- 是否必填只写 `是` / `否`。
- 条件显示的字段必须写清条件：`仅当上传方式="上传视频"时显示`。
- 文件类字段写清格式与体积：`mp4，≤100MB，拖动或点击上传`。

### T4 交互与校验表

| 触发时机 | 校验规则 | 用户提示 | 处理方式 |
| --- | --- | --- | --- |
| 输入等级名称时 | 同一平台内名称是否重复 | 名称已存在，请重新输入 | 阻止提交，高亮字段 |
| 输入门槛金额时 | 是否 ≤ 上一等级门槛 | 最低消费门槛必须高于上一等级 | 阻止提交，高亮字段 |
| 点击【确认创建】时 | 所有必填字段是否已填 | 聚焦到第一个未填字段，显示对应提示 | 阻止提交 |

- 处理方式用词：`阻止提交，高亮字段`、`阻止提交`、`仅提示不阻断`、`按钮置灰`、`自动纠正为合法值`。
- **每个表单至少 3 条校验**：唯一性、字符/数值边界、必填聚合校验。

### T5 枚举表

| 显示名称 | 说明 |
| --- | --- |
| 支付未到账 | 用户已扣款但平台未收到回调，最常见场景 |
| 客服补偿 | 因平台体验问题（如卡顿、音画不同步）给用户的补偿 |
| 其他 | 需在备注中说明具体原因 |

| --- | --- | --- |

| 审核 | 审核通过 | 剧集审核通过 |
| 导出 | 导出数据 | 导出订单报表、用户列表 |

- 有 `其他` 选项的枚举，必须同时在表单表里写"选择'其他'时备注强制必填"。
- 枚举会随业务变化时标注：`（随实际功能有所调整）`。

### T6 错误提示规范表

| 错误场景 | 前端提示文案 | 提示位置 | 后端日志记录 |
| --- | --- | --- | --- |

### T14 不包含功能表（开篇 3.4 专用）

只列"不做"不够——没写原因会被反复提案，没写评估方向需求方会以为是永久否决：

| 不包含功能 | 原因 | 评估方向 |
| --- | --- | --- |
| 原生移动 App | H5 已覆盖移动场景，App 开发与审核成本高 | 高级功能阶段评估 |
| 法币支付通道 | 当前聚焦 Web3 支付，法币通道涉及金融牌照 | 根据监管政策评估 |
| 批量导入调整 | 本期只支持单个操作，批量涉及事务与回滚设计 | 下一版评估 |

- **原因列写事实，不写"暂不考虑"**：成本、牌照、依赖未就绪、与核心场景关联度低，都是可接受的原因。
- **评估方向列只有三种写法**：`X 阶段评估` / `根据<外部条件>评估` / `不再考虑（原因）`。
- 与附录E 待确认项的分工：**本表是已经决定不做的**，附录E 是**还没定的**。

| 角色 | 类型 | 描述 | 核心权限 |
| --- | --- | --- | --- |

| 终端用户 | 用户端 | C 端使用者 | 浏览、互动、支付 |

## 三、文案范式

### 入口路径（形式随形态，规则统一）

| 形态 | 写法 |
| --- | --- |
| Web 运营管理系统 | `功能入口：管理后台 → 系统设置 → 用户管理 → 【新建用户】` |
| 移动端 APP | `页面入口：App → 首页Tab → 内容卡片点击 → 内容详情页` |
| 小程序 | `页面入口：小程序 → 首页tabBar → 商品卡片点击 → 商品详情页` |
| 移动端 H5 | `页面入口：微信分享卡片 → 落地页 → 【立即参与】→ 活动页` |
| Web 官网 | `页面入口：官网 → 顶部导航【产品】→ 功能介绍页` |

- 分隔符固定用 `→`（全角箭头，两侧留空格）。
- 按钮名用 `【】`：`【新建用户】`、`【查看详情】`、`【确认补发】`。
- 弹窗打开方式要写：`点击【新建用户】后，从屏幕中间弹出表单窗口。`

### 二次确认弹窗

必须写成**完整可上线的整句**，包含：动作 + 对象（带 `【】`）+ 后果 + 反问。

```
即将对【架空历史】分类进行删除，删除后将影响所有已关联的剧集。确认继续吗？
即将为用户【追剧小能手】补发【《前夫跪求复婚》全集】，确认继续吗？
即将对订单【WX202609011432001】发起退款 ¥0.99，并回收该剧集权益。确认继续吗？
```

### 状态与操作的联动

```
禁用/启用：状态为启用时，按钮显示"禁用"，点击后状态变更为禁用，反之一样。需要二次确认提示弹窗。
【退款】只有支付成功状态的订单可见，并可以操作；操作后修改订单状态为：已退款。
【补单】只有非支付成功状态的订单可见，并可以操作；操作后修改订单状态为：支付成功。
```

### 指标卡九行式

每个指标卡固定写这九行（不适用的写"不适用"，不要整行省略）：

```
总收入：
  定义：平台累计到昨日的收入金额（所有已支付订单金额总和，不含退款）
  时间口径：累计，不受顶部时间筛选器影响
  计算方式：所有已支付订单的金额总和 - 退款总金额
  主数字格式：金额格式，保留两位小数，千位分隔符（如 125,680.50）
  环比对比：环比上月（自然月同期对比）
  环比计算：（本月累计收入 - 上月累计收入）/ 上月累计收入 × 100%
  环比展示：正增长绿色↑，负增长红色↓，单位百分比
  展示文案：环比上月 +18%
  特殊处理：若上个月无数据，显示"—"
```

**受筛选器影响的指标**额外补一段不同范围的环比口径：

```
  不同时间范围的环比口径：
    昨日 → 较前日
    近 7 天 → 较上一个 7 天（不含今天）
    近 30 天 → 较上一个 30 天（不含今天）
    自定义 → 较上一个等长周期
```

**百分比类指标的环比是"百分点差值"，不是百分比变化率**——必须写清楚，这是最常见的口径事故。

### 图表规格

```
收入趋势：
  图表类型：折线图 + 面积图效果（渐变填充）
  数据维度：每日收入金额
  横轴：日期（按时间筛选器范围，不含今日）
  纵轴：收入金额
  数据点：每天 1 个数值，用圆点标记
  面积填充：折线下方渐变半透明填充，增强视觉层次
  交互：鼠标悬停显示具体数值（日期 + 金额）
  统计口径：已支付订单金额 - 当日退款
  时间范围：受顶部时间筛选器控制
  数据说明：展示筛选范围内每一天的收入金额
  空数据表现：无数据时显示空态插图 + 文案"当前筛选条件下暂无数据"
```

### 数据时效声明

涉及统计的页面开头必须写：

```
今日数据不统计，实时查询消耗过大，数据采用定时器跑批后存入数据库。
数据采用每日 02:00 进行统计。
```

## 四、禁用写法

| 禁用 | 改成 |
| --- | --- |
| "提示错误信息" / "给出相应提示" | 写出原文：提示"账号或密码错误，请重新输入" |
| 示例值写 "xxx" / "字符串" / "某某" | 写具体假数据：`COMP20260902001`、`2026-09-02 10:15:23` |
| "支持筛选" | 列出 T1 筛选条件表 |
| "字段若干" / "包含基本信息" | 列出 T2/T3 字段表，一个不漏 |
| "做必要的校验" | 列出 T4 交互与校验表 |
| "展示图表" | 按图表规格九行写 |
| "环比展示" 而不说口径 | 写出环比计算公式和百分点 vs 百分比 |
| 用散段落罗列多个同类项 | 转成表格 |
| 写技术实现（用 Redis 缓存、加索引） | 只写"要求列表首屏 ≤ 2 秒"，实现交给 `lld-design` |
| 用 emoji 当结构图标 | 用文字或说明 SVG 图标族 |
| 页面写完不给 UX 规范段 | 补 T13 |
| 页面写完不配原型图 | 补一张，弹窗单独一张（见 `wireframe.md`） |
| 原型图 PNG 用中文文件名 | 改成纯 ASCII，否则 Word 导出静默丢图 |

## 五、语言风格

- 全中文，专业但不啰嗦；一句话说清一件事。
- 数字、英文、代码与中文之间不强制加空格，但同一份文档内保持一致。
- 金额统一写 `¥` 或 `（元）` 后缀，二选一贯穿全文。
- 时间格式统一：日期 `2026-09-02`，日期时间 `2026-09-02 14:32:15`，列表展示可用 `2026-09-02 10:15`。
- 枚举分隔符统一用 ` / `：`正常 / 已冻结 / 已注销`。
- 范围符号用 `≥ ≤ >` 而不是 `大于等于`。
