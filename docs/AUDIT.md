# 贯通检查记录（v1.0 发布前）

打包前对全链路做了十轮检查，共修 **69 处**。前七轮查文档一致性，第八轮起做真实端到端跑测。
记在这里是因为**其中大半是「文档写着但从未生效」的问题**，对后续维护有参考价值。

## 方法论（比结论更有用）

1. **文档一致 ≠ 能跑通。** 七轮文档检查全过之后，第一次真导出就丢了图。
2. **一个规则有多个维度时，实跑样本要覆盖维度组合。** 第八轮测试项目所有文档都在 `docs/` 根下，
   所以「图片目录随文档落盘位置变化」这一维永远测不出来，第九轮才暴露。
3. **判断技能能否塞进流程某阶段，要 grep 它认不认识流程契约**（`SPEC_SOURCE`、落盘路径），
   不要看描述像不像。
4. **门禁写 glob 不写精确名**——技能自己决定文件名的架构下，精确名必然失效。
5. **grep 假阳性有两种对称来源**：中文库里 grep 英文缩写（`ASCII` 命中「ASCII 线框」）、
   grep 中文单字（`档位` 命中「文档」）。
6. **扫路径要带 `--include='*.sh' --include='*.py'`**——只扫 `.md` 会漏掉脚本内部的注释路径。
7. **批量插入内容后要逐个核对落点章节**，不能只核对"插进去了"。

## 十轮各自查到什么

| 轮 | 主要发现 |
| --- | --- |
| 1 | 引擎从旧流水线原样搬来，只写到阶段 0–9，新增的 -2/-1/10 在六处引擎位置全是孤儿；进度汇报分母写死 `/10` |
| 2 | 三个裁剪有硬输入缺口（跳过阶段 3 但阶段 5/9 声明 `roadmap.md` 为输入）；阶段 0 不知道阶段 -1 已定滩头会重做全市场扫描 |
| 3 | `pm-prd-writer` 被误设为阶段 5 默认档，但它不登记 `SPEC_SOURCE`，会断在 5→6 交接；**门禁与断点续跑用精确文件名，9 个阶段里 7 个不匹配，从未真正生效过** |
| 4 | `.agents/` 外部资源包路径全库悬空（14 个技能），**Word 导出功能实际是坏的**；44 处改同级相对路径，SRS 门禁规则建库内副本 |
| 5 | 目录约定实际有三套而流程只认一套；**顾问团 7 个技能名册只有人名书名、没有技能 ID**，总控无法路由 |
| 6 | 设计稿链路（598 行契约）整条不在流程视野里；写清「设计稿 vs 前端原型」「两个标注」两处歧义 |
| 7 | 静默丢图规则只在 memory 里、不在技能里（10 个技能只有 2 个写了）；`common/README.md` 三处写死用户名绝对路径 |
| 8 | **真实端到端跑测**：13 门禁全过、断点续跑判定准确、SRS 门禁正确拦截；跑测抓到丢图规则不完整——路径形式也只有 `images/` 一种可用 |
| 9 | 「与文档同级的 images/」按文档实际落盘目录算，整条「生成图表 → 插文档 → 导出」链路一直断着；修 6 处错写法（含我自己第八轮写错的两句） |
| 10 | xlsx 是独立导出链，payload 必须用 `data` 二维数组（用 `headers`/`rows` 得到无 worksheet 的空壳）；脚本内部还有 2 处 `.agents/` 注释；1 处警告插错章节 |

## 实测通过的链路

- 13 个阶段门禁（glob）、断点续跑判定、SRS 门禁拦截、裁剪输入缺口的替代来源
- `wireframe.py` + `render.sh`（qlmanage）+ `png_crop.py`：SVG→PNG，1200×1200 裁到 1152×270
- `diagram-generator`：draw.io XML 校验 + 渲染 PNG
- Word 导出含嵌图，两个目录层级（`docs/SRS/images/`、`docs/PRD/images/`）各验一次
- xlsx 导出：`dimension A1:C4`，共享字符串齐全

## 未实测的两处

`ui-ux-pro-max` 的设计稿交付（三张预览墙，需要真实 PRD+SRS）、`annotation` 的代码注入（需要真实 Vue 项目）。
这两条要在真实项目里才能验。
